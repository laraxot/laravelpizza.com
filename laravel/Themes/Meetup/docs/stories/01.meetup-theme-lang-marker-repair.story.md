# Riparazione marker di sync nel tema Meetup

## Obiettivo

Le traduzioni del tema sono il testo del sito pubblico: un `<<<<<<<` in `lang/*/auth.php` o `events.php` e' un
errore di parsing che rompe login, registrazione, reset password ed elenco eventi per i visitatori, anche se
PHPStan analizza solo `Modules/`. Le Blade con marker non compilano. Risultato richiesto: file che fanno quello
per cui esistono, con le chiavi di entrambi i lati dove non si contraddicono.

## Scope

Solo `laravel/Themes/Meetup/lang/{it,en,de,es}/{auth,events}.php` e quattro Blade sotto
`resources/views/`. Niente `.md`, niente asset, nessun segnaposto nelle Blade (la regola 0d/0e del repository
vale: icone con `x-filament::icon`, URL con `LaravelLocalization::localizeUrl`).

## Lang: scopo e risoluzione

Ogni file lang e' un array puro, senza classi. Il lato "locale" (HEAD) e' il piu' recente: porta le pagine
auth ridisegnate (`auth-card`, `auth-field`) e i filtri eventi (`events.search.*`).

| File | Scopo | Risoluzione | Chiavi/righe scartate |
|------|-------|-------------|-----------------------|
| `lang/it/auth.php` | testi di login, reset, conferma, verifica email | lato locale per ogni hunk | `verify.resent.message`; `password.reset.title` "Reimposta la password" -> "Scegli una nuova password"; `password.confirm.title` "Conferma la tua password" -> "Conferma la password" |
| `lang/en/auth.php` | idem | idem | `verify.resent.message`; `password.reset.title` "Reset password" -> "Choose a new password" |
| `lang/de/auth.php` | idem | idem | `verify.resent.message`; `password.reset.title`; `password.confirm.title` "Bestätigen Sie Ihr Passwort" -> "Passwort bestätigen" |
| `lang/es/auth.php` | idem | idem | `verify.resent.message`; `password.reset.title` "Restablecer contraseña" -> "Elige una nueva contraseña" |
| `lang/it/events.php` | etichette stato e ricerca eventi | unione: il lato remoto era un sottoinsieme | `status.past.label` "Eventi passati" -> "Passati" (etichetta breve del filtro; "Eventi passati" resta in `search.show_past`) |
| `lang/de/events.php` | filtri eventi | unione: il lato remoto era vuoto | nessuna |
| `lang/es/events.php` | filtri eventi | unione: il lato remoto era vuoto | nessuna |

Perche' `verify.resent.message` e' stato scartato: sullo stesso nodo il lato locale ha una stringa
(`'resent' => '...'`), quello remoto un array. PHP non ammette entrambi. L'unico chiamante e'
`pages/auth/verify.blade.php`, che stampa `__('pub_theme::auth.verify.resent')` come stringa; nessun altro file del
repository usa `pub_theme::auth.verify.resent.message` (quello in `Modules/User` appartiene al namespace `user::`).
I valori di `password.reset.title` e `password.confirm.title` scartati erano del vecchio design; le pagine attuali
(`[token].blade.php`, `confirm.blade.php`) leggono la formulazione nuova insieme a `subtitle`, `password`,
`password_confirmation`, `submit`.

Allineamento: it, en, de, es hanno le stesse 48 chiavi appiattite in `auth.php`. `events.php` non e' allineato tra
lingue (es. `en` ha `fields.*` e `actions.*`, `it` ha le chiavi senza prefisso): divergenza precedente ai marker,
non toccata.

## Blade: scopo e risoluzione

| File | Scopo | Risoluzione | Scartato |
|------|-------|-------------|----------|
| `pages/auth/logout.blade.php` | GET `/auth/logout`: mostra "disconnessione in corso" ed esegue `LogoutAction` | lato locale | vecchio `<h1 wire:init>` senza layout; la chiave `logout.goodbye.message` resta nei lang |
| `pages/auth/password/reset.blade.php` | richiesta del link di reset | lato locale (`x-ui.auth-card` + `x-ui.auth-field`, link con `localizeUrl`) | form con `x-ui.input` e `route('login')` non localizzato |
| `pages/auth/password/[token].blade.php` | nuova password da link email | lato locale | layout `x-layouts.main` con logo duplicato e `route('home')` |
| `components/blocks/events/list.blade.php` | elenco eventi con filtri Alpine | lato locale | SVG inline (vietato dalla regola 0d) e badge `event.status` / `common.badges.*`: il payload espone `timing_status` (`Modules/Meetup/app/Models/Event.php`) e le chiavi `event.status.*.label` esistono in it/en/de/es |

In `reset.blade.php` e `[token].blade.php` ho aggiunto i docblock `@see Themes/Meetup/docs/authentication-ui-ux.md`
alle classi Volt anonime (e al metodo `sendResetPasswordLink`), come richiede la regola 0f.

## Note di provenienza

Mentre analizzavo, un altro scrittore (non identificato; non lo script di sync, che girava in `base_ptvx_fila5`)
ha risolto gli stessi file; il commit `df495a3ef` li contiene gia' senza marker. Non ho sovrascritto nulla:
ho confrontato ogni file con i due lati del commit conflittuale `6291f121d` e con le chiavi usate dalle Blade.

## Verifica

- Marker in `Themes/Meetup/**/*.php` e `*.blade.php`: 0.
- `php -l` verde su tutti i file; `include` dei 7 file lang restituisce un array.
- Pest: `ThemeIntegrityTest`, `UniqueVoltFragmentNamesTest`, `FolioPagesWithoutSideEffectsTest`,
  `Feature/Security/LogoutPageTest` verdi.
- `NoMergeConflictMarkersTest` e' rosso a livello di repository per file di altre corsie (documentazione `.md`);
  nessun file del tema Meetup in codice ne e' piu' l'origine.

## Anomalie non legate ai marker

- `Themes/Meetup/docs/development-workflow-css-js-changes.md` e `Themes/Meetup/.gitignore` contengono ancora
  `=======`/marker: fuori scope di questa corsia (`.md`) o non PHP.
- `Themes/Meetup/postcss.config.js` risulta modificato nel working tree da un'altra attivita'.
