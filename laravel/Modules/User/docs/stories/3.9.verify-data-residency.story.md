# 3.9: Data residency: verify EU-only deployment

**Story ID:** 3.9
**Epic:** 3: Access Control & Security
**Slug:** verify-data-residency
**Status:** backlog

## Story

As a compliance-responsible PA admin,
I want an automated check confirming the application and its logging/storage dependencies are deployed only within the EU,
so that personal data never leaves EU jurisdiction and the PA stays compliant with GDPR and Italian public-sector law without a manual audit each release.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. A verification routine (artisan command or test) checks that the application's configured deployment region is an EU region (Vercel EU region, per architecture) and fails loudly if a non-EU region is configured. [Source: prd.md#NFR-SEC-004: "Deployment: Vercel EU region only"]
2. The same or a companion check enumerates configured logging/monitoring integrations and fails if any US-based service (explicitly: Sentry, Datadog) is configured. [Source: prd.md#NFR-SEC-004: "No US export: no log shipping to US-based services (no Sentry, Datadog)"]
3. The check's failure output references the compliance basis (D.Lgs. 165/2001 and GDPR Art. 44 adequacy) so a future developer understands why the check exists, not just that it failed. [Source: prd.md#NFR-SEC-004: "Compliance: D.Lgs. 165/2001 + GDPR Art. 44 (adequacy)"]
4. The verification routine is designed to be invoked as a CI gate step; this story delivers the check itself, not the CI workflow wiring (Epic 5 scope). [Source: prd.md#NFR-SEC-004: "Verify: CI gate checks deployment region"]
5. Automated test proves the check correctly passes for an EU-region config and fails for a non-EU/US-service config. [Inference: NFR-SEC-004 states the gate must exist and verify region; a testable pass/fail behavior is the natural verification of "CI gate checks deployment region" without over-specifying implementation.]

## Tasks / Subtasks

- [ ] Create an artisan command (e.g., `Modules/User/app/Console/Commands/VerifyDataResidency.php`) reading the app's deployment-region config/env and asserting it matches an EU-region allowlist (AC: #1)
- [ ] Extend the same command to scan configured service providers/config for Sentry/Datadog (or equivalent non-EU logging SDKs) and fail if present (AC: #2)
- [ ] Write clear, compliance-referencing failure messages citing D.Lgs. 165/2001 and GDPR Art. 44 (AC: #3)
- [ ] Document (docblock/README note within the command file) that Epic 5 is expected to invoke this command as a CI step: do not create or edit `.github/workflows/` files (AC: #4)
- [ ] Write unit/feature tests for both pass and fail conditions of the command (AC: #5)

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- **Test type:** Unit/feature tests (Pest) around the artisan command's exit code and output; no e2e, no actual deployment/infra test (this story cannot provision real Vercel infrastructure).
- **Fixtures:** config/env overrides simulating an EU-region deployment (pass case) and a non-EU-region or Sentry/Datadog-configured deployment (fail case).
- **Scenarios to prove each AC:**
  - AC #1: command exits `0` for EU-region config; exits non-zero for a non-EU region value.
  - AC #2: command exits non-zero when a Sentry or Datadog service provider/config key is detected, even if the region check alone would pass.
  - AC #3: failure output string contains references to "D.Lgs. 165/2001" and "GDPR Art. 44" (or equivalent readable compliance references).
  - AC #4: confirm no `.github/workflows/` file exists or was modified by this story (scope-boundary check, not a functional test).
  - AC #5: both pass and fail branches covered by at least one test case each.
- **Edge cases:** missing/unset region env var (should fail closed: treat as non-EU/unknown, not pass by default); a config value that is an EU-adjacent but non-approved region (e.g., a non-EU code that superficially resembles an EU one): command must use an explicit allowlist, not a fuzzy/pattern match.
