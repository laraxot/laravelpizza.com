## Story

Come **maintainer User**,
voglio **una sola implementazione login/register/password/logout**,
così che **`ViewCopyAction` e i form HTTP orfani non possano divergere dai widget**.

## Acceptance Criteria

1. Assenti: `Auth\Login`, `Register`, `Logout`, `AuthLogout`, `Verify`, `Passwords\Email`, `Passwords\Reset`, `Passwords\Confirm`. [Source: livewire-widget-prd.md#FR-C004] [Source: livewire-inventory.md]
2. Grep modulo: zero `ViewCopyAction` sotto `app/`. [Source: livewire-widget-prd.md#FR-C005] [Source: livewire-widget-architecture.md#adr-c005]
3. Prima del delete: grep temi + User views per `@livewire` verso quelle classi; se un Blade orfano le chiama, si sposta al widget **senza** reintrodurre HTTP. [Source: livewire-widget-tech-spec.md#rischi]
4. SSoT logout: un solo widget documentato nella story (scegliere tra `Widgets\LogoutWidget` e `Widgets\Auth\LogoutWidget`). Nessuna terza classe. [Source: livewire-widget-tech-spec.md#cluster-b]
5. SSoT reset: scegliere `PasswordResetWidget` o `ResetPasswordWidget`. [Source: livewire-widget-tech-spec.md]
6. `AdminPanelProvider` non è in scope. [Source: livewire-widget-architecture.md#adr-c004]
7. Test `LoginComponentTest` aggiornato al widget o rimosso se duplica i test widget. [Source: livewire-widget-tech-spec.md]
8. Se `AuthLogout` aveva `htmlspecialchars(): array given`, il ritiro chiude il bug HTTP; grep che il widget SSoT logout non passi array in `{!! !!}` / `{{ }}` HTML. [Source: livewire-inventory.md]

### Scoperte fuori scope (NON corrette, solo documentate: vedi motivazione sotto)

Durante la stesura della nuova copertura Feature è emerso che il widget SSoT `Auth\LoginWidget` (registrato e "vivo" per convenzione, ma **mai stato testato prima d'ora**) è oggi **completamente non renderizzabile**, per due bug preesistenti e indipendenti dallo scope di questa story, entrambi introdotti dallo stesso commit `0701a777a` ("feat(gitmodules): add new submodule for Setting module": messaggio non correlato, chiaro danno collaterale da commit non atomico):
1. `Modules/User/lang/it/login.php` ritorna `int(1)` invece di un array (file troncato a sole 3 righe, `return [...]` sparito) → fatale `array_replace_recursive(): Argument #2 must be of type array, int given` per qualunque `__('user::login.*')` in locale `it`.
2. `Modules/User/resources/views/filament/widgets/auth/login.blade.php` troncato da 111 righe a una sola riga orfana (`</div>` senza tag di apertura) → `Livewire\Exceptions\RootTagMissingFromViewException` su qualunque render.

Impatto: la pagina di login reale (se questo è il widget effettivamente montato) è oggi rotta in produzione. **Non corretto in questa sessione**: entrambi i file sono fuori dall'Owned File/Module Scope dichiarato della story (`app/Http/Livewire/Auth/**`, `resources/views/livewire/auth/**`, un solo test file), e la story stessa istruisce di non improvvisare fuori scope ma di documentare e fermarsi. **Richiede una story/fix urgente separata**: probabilmente lo stesso commit ha danneggiato altri file nello stesso modo (non verificato oltre questi due, fuori scope). I 4 test che dipendono dal render sono marcati `->skip()` con motivazione esplicita nel file; il 5° (delega form/schema, non dipende dal render) passa realmente.

### Follow-up 2026-09-21: fix 500 reale in produzione + audit blast radius commit 0701a777a

Segnalato dall'utente: `TypeError` reale su `GET /user/admin`
(`array_replace_recursive(): Argument #2 must be of type array, int given`,

chiamante inizia per `dashboard`/`list`/`get`/`manage`/`edit`/`view`/`create` e non
lascia resto) troncato dallo stesso commit `0701a777a` a 4 righe senza `return` →
`require` ritorna `int(1)`, non array.

Fix (git forward-only, `git show 0701a777a^:<path>` + `Write`/`cp`, mai checkout/revert):
1. `Modules/User/lang/it/.php`: ripristinato `return [...]`. Verificato: `curl` sulla
   stessa route → `302` (era `500`).
2. `Modules/User/lang/it/client.php`, `role.php`, `view_user.php`: stesso bug
   (0 `return`), stesso commit, ripristinati e verificati (`php -l` + `is_array`).
