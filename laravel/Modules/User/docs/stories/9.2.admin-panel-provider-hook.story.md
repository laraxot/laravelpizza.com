## Story

Come **operatore del panel**,
voglio **che `/admin` monti il widget SuperAdmin al posto del Livewire `profile.super-admin`**,
così che **il user menu non dipenda più da quell’alias**.

## Acceptance Criteria

1. Il `registerRenderHook` del SuperAdmin (oggi `Blade::render("@livewire('profile.super-admin')")`) monta `SuperAdminWidget::class` via `@livewire('…FQCN…')`. [Source: tech-spec.md#adminpanelprovider] [Source: prd.md#FR-003]
2. Lo hook usa `Filament\View\PanelsRenderHook::USER_MENU_BEFORE` (costante), non solo la stringa magica, **per il blocco SuperAdmin**. [Source: tech-spec.md#adminpanelprovider]
3. L’hook `team.change` (`Blade::render("@livewire('team.change')")`) è **byte-invariato** in questa story. [Source: architecture.md#adr-004]
4. Non si decommenta `View::make('user::badges.super-admin')`. [Source: tech-spec.md#adminpanelprovider] [Source: prd.md#FR-002]
5. Nessun `->widgets([SuperAdminWidget::class])`, nessun `userMenuItems` nuovo, nessun `pages()` per questo toggle. [Source: tech-spec.md#adminpanelprovider] [Source: prd.md#FR-006]
6. `parent::panel($panel)` resta la prima trasformazione del panel. [Source: tech-spec.md#adminpanelprovider]

## Spec del blocco (contratto)

**Prima:**

```php
FilamentView::registerRenderHook(
    'panels::user-menu.before',
    static fn (): string => Blade::render("@livewire('profile.super-admin')"),
);
```

**Dopo (da implementare in 9.2, non in questa sessione docs):**

```php
FilamentView::registerRenderHook(
    PanelsRenderHook::USER_MENU_BEFORE,
    static fn (): string => Blade::render(
        '@livewire(\'' . SuperAdminWidget::class . '\')',
    ),
);
```

Il Livewire HTTP può restare su disco fino a 9.3: dopo 9.2 semplicemente non è più montato.
