# 8.2: PHPStan: falsi positivi `it()->todo()` / `uses()->group()` (void chain)

## Contesto

Task da coordinatore fleet phpstan-swarm: 38 errori PHPStan in 16 file di
`Modules/User/tests/`, tutti dello stesso pattern:

```
[method.nonObject] Cannot call method todo() on null.
[function.void] Result of function it (void) is used.
```

(idem per `uses(...)->group(...)`).

## Causa radice

`laravel/phpstan.neon` ha **deliberatamente** disabilitato l'extension Pest
per PHPStan:

```
# - ./vendor/pestphp/pest-plugin-phpstan/extension.neon
```

Senza quell'extension, PHPStan non conosce le firme reali di `it()`, `test()`,
`uses()`, `describe()` (che in Pest restituiscono oggetti `PendingCalls\*`
concatenabili con `->todo()`/`->group()`), e le tratta come funzioni `void`
non tipizzate: da cui i due errori gemelli su ogni riga che le concatena.

Non è un bug nel codice applicativo: è un limite noto e già accettato del
setup PHPStan del monorepo. La convenzione di risoluzione esiste già altrove
nel repo (es. `Modules/Incentivi/tests/**`, decine di file) con lo stesso
identico commento: questa story applica la stessa convenzione a `User`,
estendendola al pattern gemello `it()->todo()` (non ancora documentato altrove
nel repo prima d'ora).

## Cosa è stato fatto

Aggiunto `@phpstan-ignore-next-line method.nonObject, function.void` con
motivazione inline, sulla riga immediatamente sopra ciascuna chiamata
`uses(...)->group(...)` o `it(...)->todo()` incriminata. Nessuna modifica al
codice di test, nessuna modifica a `phpstan.neon` (sacro), nessun `mixed`
introdotto.

File toccati (16):

1. `tests/Feature/Filament/Clusters/Passport/Resources/OauthAccessTokenResourceTest.php` (3 occorrenze `it()->todo()`)
2. `tests/Feature/UserCommandIntegrationTest.php` (2 occorrenze `it()->todo()`)
3. `tests/Unit/Actions/Socialite/Utils/EmailDomainAnalyzerTest.php` (`it()->todo()`)
4. `tests/Unit/Adapters/Socialite/UserNameFieldsResolverAdapterTest.php` (`uses()->group()`)
5. `tests/Unit/Enums/UserEnumsTest.php` (`it()->todo()`)
6. `tests/Unit/Http/Livewire/Auth/LoginComponentTest.php` (`uses()->group()`)
7. `tests/Unit/Listeners/LogoutListenerBehaviorTest.php` (`uses()->group()`)

## Blocker fleet-wide riscontrato (fuori scope, non risolto qui)

`php -d memory_limit=-1 ./vendor/bin/phpstan analyse Modules/User` va in
**PHP Fatal error** (non un errore PHPStan, un vero crash del processo)
durante il bootstrap:

```
Cannot override final method Modules\Xot\Filament\Resources\Pages\XotBaseListRecords::getTableColumns()
in Modules/Ptv/app/Filament/Resources/CategoriaProproResource/Pages/BaseListCategoriaPropros.php:28
```

Stesso pattern "override di metodo final" già noto e in corso di bonifica sul
resto della fleet (vedi commit `ad27587eba` in root: "bootstrap phpstan
sbloccato ... 43 file/4 moduli"), ma **`Modules/Ptv` non è tra i moduli già
sistemati** ed è fuori dal mio scope (`Modules/User`). Questo impedisce
qualunque run completo di `phpstan analyse Modules/User` in questo momento
(anche scoping il path, il bootstrap dell'app Laravel/Filament carica comunque
tutte le risorse registrate). Segnalato al coordinatore; non toccato
`Modules/Ptv`.

Verifica alternativa fatta per ciascun file: `php -l` (tutti puliti) +
lettura diretta del pattern rispetto alla convenzione già in produzione in
`Modules/Incentivi`.

## Testing

- `php -l` su ciascuno dei 16 file → nessun errore di sintassi.
- `php -d memory_limit=-1 ./vendor/bin/phpstan analyse Modules/User
  --no-progress` → **blocked** da fatal error in `Modules/Ptv` (fuori scope,
  vedi sezione blocker).
- `./tools/phpmd.sh Modules/User` / `./vendor/bin/pest Modules/User` → run
  molto lenti/timeout in questo ambiente (DB test `10.100.200.53`
  irraggiungibile: vedi memoria `project-test-db-unreachable-drives-skips`);
  non bloccanti per questa story dato che le modifiche sono solo commenti
  PHPDoc senza impatto runtime.
