# 12.4: Resource Passport SSoT nel cluster (fine doppioni radice)

**Story ID:** 12.4  
**Epic:** 12: Audit UI/Filament modulo User  
**Slug:** oauth-dup-resources-ssot  
**Status:** backlog

## Story

Come **sviluppatore User**,
voglio **una sola resource Filament per ogni entità Passport (OAuth)**,
così che **non esistano più tre copie divergenti dello stesso schema/table col rischio di una UI che non valida davvero**.

## Evidenza (sha confrontati sul disco 2026-09-22)

- `OauthClientForm` in 3 namespace con contenuti **diversi**:
  `Resources/ClientResource/Schemas/OauthClientForm.php` (67 righe), `Resources/OauthClientResource/Schemas/OauthClientForm.php` (41), `Clusters/Passport/Resources/OauthClientResource/Schemas/OauthClientForm.php` (39).
- Diff chiave: `ClientResource` fa `->unique('clients', 'name')` (riga 23) e usa `TextInput` per secret/flag booleani; la copia cluster fa `->unique('oauth_clients', 'name')` con `Select provider` e `TextInput numeric`: **validazione in conflitto** («clients» vs tabella reale del modello).
- `OauthClientsTable` ×3 (sha `cccc6ae8`, `74bfc8fc`, `0480ed8e`).
- `Clusters/Passport/Resources/OauthAccessTokenResource/Pages/EditOauthAccessToken.php` **e** `EditOauthAccessTokens.php` (primo: nav label 'Edit Access Token' e icon; secondo: XotBaseEditRecord + `DeleteAction`) + una terza copia `Resources/OauthAccessTokenResource/Pages/EditOauthAccessTokens.php`.
- Resource duplicate radice: `Resources/OauthClientResource`, `Resources/OauthPersonalAccessClientResource`, `Resources/OauthAccessTokenResource` (e sorelle AuthCode/RefreshToken).

## Acceptance Criteria

1. `Resources/{OauthClientResource,OauthAccessTokenResource,OauthPersonalAccessClientResource}` (radice) e relativi `{Pages,Schemas,Tables}` assenti → sostituiti da `Clusters/Passport/Resources/*` (esistenti).
2. **Un solo** `OauthClientForm` in tutto `app/Filament`; `->unique()` sulla tabella reale del modello (`oauth_clients`); `secret` coerente (criptorilasciabile per il modello, niente `TextInput` che lo riprende); un solo `EditOauthAccessToken*` (`EditOauthAccessToken`) con delete action dichiarata.
3. Nessuna migrazione: `oauth_clients.name` già unique nel DB → il `unique(oauth_clients...)` diventa gestito, non più "più permissivo".
4. L'intento corrente delle entry radice che non è coperto dal cluster (eventuali label/helper già traduite in 12.2) è **tracciato** prima della cancellazione, non perso.
5. `rg "OauthClientResource|EditOauthAccessTokens" Modules/User/app/Filament` → solo occorrenze nel cluster.
6. Test esistenti Passport verdi (`PassportDashboardNewCredentialsTest`, `OauthAccessTokenResourceTest`, `ClientsRelationManagerAssociateTest`): aggiornare i riferimenti radice→cluster senza ridurre la copertura.
