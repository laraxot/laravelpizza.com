# 9.6: icone crown Marvel-style animate per SuperAdmin widget

**Richiesta utente**: "metti una icona stile marvel per superadmin, qualcosa se
vuoi divertente elegante stile outline, con leggera animazione fatti i 2 svg".

## B (business)

Sostituisce gli `heroicon-o-shield-*` della story 9.5 (che a sua volta aveva
sostituito il vecchio `fas-chess-king` + CSS `rotate-180`, story 9.1) con 2 SVG
custom del modulo, coerenti con l'estetica "corona" storica del widget ma
disegnati da zero in stile outline, con micro-animazione hover.

## M (analisi)

**Come funziona il set icone custom `user-*`** (non ovvio, verificato leggendo
il codice, non per sentito dire): `Modules\Xot\app\Providers\XotBaseServiceProvider::registerBladeIcons()`
registra automaticamente `Modules/<Nome>/resources/svg/` come set blade-icons
con prefix `<nomelower>`. Per `User`: ogni file in
`Modules/User/resources/svg/<file>.svg` diventa disponibile come icona
`user-<file>`. Non serve config, non serve registrazione manuale.

Convenzione animazione gia' presente nel modulo (vista su
`permission-animated.svg`, `role-animated.svg`): `viewBox 0 0 24 24`,
`stroke="currentColor"`, `stroke-width="2"`, classi su singoli elementi +
`<style>` con keyframes innescati da `svg:hover`, MAI animazione infinita di
default (leggera = solo su hover, non un loop perenne che gira anche quando
l'utente non guarda). Seguita qui invece di inventare un pattern nuovo.

## Race multi-agente trovata prima di scrivere

Nella working tree, non committato, un'altra sessione (stesso prompt
utente, lanciato in piu' sessioni in parallelo: pattern gia' noto,
vedi `multi-agent-same-prompt-parallel-superadmin-icons.md`) aveva gia'
scritto un tentativo "glow filter + pulse infinito" con 2 bug:
1. File nuovo `super-admin.svg` (CON trattino) invece di sovrascrivere
   `superadmin.svg` (SENZA trattino, il nome che il service provider
   davvero risolve): icona orfana, mai raggiungibile da `icon="user-superadmin"`.
2. Classe CSS `animate-pulse` ridefinita dentro `<style>` dentro l'SVG:
   e' il nome di un'utility class REALE di Tailwind, gia' usata altrove
   nell'app: ridefinirla dentro un `<style>` non scoped avrebbe rischiato
   di rompere altre animazioni "pulse" ovunque nella pagina (CSS globale,
   non isolato all'SVG). Non usata.

File orfano cancellato, non riusato: architettura diversa (hover invece di
loop infinito, classi non ambigue).

## D (dettagli implementazione finale)

`Modules/User/resources/svg/superadmin.svg` (stato attivo):
- corona zigzag (`class="crown"`, path chiuso `M4 18 L4 9 L8 13 L12 6 L16 13 L20 9 L20 18 Z`)
- gemma al vertice centrale (`class="gem"`, cerchio)
- hover: corona scala 1.1, gemma "twinkle" (scala 1 -> 1.6 -> 1, 0.9s)

`Modules/User/resources/svg/negate-superadmin.svg` (stato rinunciato):
- stessa corona (stessa shape, coerenza visiva tra i 2 stati: stesso difetto
  gia' corretto nella story 9.5 per gli heroicon, riapplicato qui: NON
  mischiare famiglie di icone diverse tra i 2 stati)
- niente gemma (corona "spenta"): la presenza/assenza della gemma da sola
  comunica lo stato, oltre al colore
- diagonale sempre visibile (`class="slash"`, non nascosta dietro hover:
  deve comunicare lo stato anche senza interazione)
- hover: corona scala 0.92 (si "spegne" invece di crescere), diagonale
  "flash" opacita (0.6s)

`super-admin.blade.php`: `icon="user-superadmin"` / `icon="user-negate-superadmin"`,
colori Filament `warning` (attivo, oro/regale) / `gray` (rinunciato, spento).
`stroke="currentColor"` nell'SVG eredita il colore dal color prop di Filament,
stesso meccanismo gia' verificato con gli heroicon nella story 9.5.
