# 5.1: PHPStan Level 10: resolve remaining User/Lang type debt

> Questa story combinata resta come storico. La consegna canonica è stata separata per ownership in `7.1-USER` e `7.1-LANG`; le sezioni LOCKED sottostanti non sono state riscritte.

**Story ID:** 5.1
**Epic:** 5: Code Quality & Infrastructure
**Slug:** user-lang-phpstan-debt
**Status:** backlog

## Story

As the tech lead accountable for the PHPStan Level 10 gate,
I want the `User` and `Lang` modules to pass `phpstan analyse` at Level 10 with zero errors,
so that these two modules stop being the largest blockers to the "0 errors across 35/35 modules" quality bar that every other epic depends on.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. `cd laravel && ./vendor/bin/phpstan analyse Modules/User --no-progress` exits 0 with zero reported errors, using the existing `laravel/phpstan.neon` unmodified (no `-c`, no `--level` override, no new neon file). [Source: prd.md#NFR-CQ-001: "PHPStan Level 10 (0 errors), all 35 modules... Enforcement: CI gate blocks merge if PHPStan L10 fails"]
2. `cd laravel && ./vendor/bin/phpstan analyse Modules/Lang --no-progress` exits 0 with zero reported errors, under the same constraint as AC #1. [Source: prd.md#NFR-CQ-001: "Current: 28/35 modules pass (174 errors in User, Lang, etc.)"]
3. No touched method signature contains an unresolved `mixed` return/param type where a concrete type is determinable, and no `@phpstan-ignore` / `ignoreErrors` suppression is added to reach green. [Source: prd.md#NFR-CQ-001: "zero any types"]
4. Every `get{X}Attribute()` accessor added or edited during this story has its "twin" `get{X}()` pure method present on the same class, per repo convention. [Source: docs/wiki/rules/accessor-twin-method.md: "ogni `get{X}Attribute()` deve avere il gemello `get{X}()` sulla stessa classe composta"]
5. `git diff --stat laravel/phpstan.neon` is empty after this story: the file is byte-identical to its state before the story started. [Source: docs/wiki/rules/phpstan-neon-immutable.md: "Solo l'UTENTE umano può modificarlo. Gli agenti AI mai."]

## Tasks / Subtasks

- [ ] Run `cd laravel && ./vendor/bin/phpstan analyse Modules/User Modules/Lang --no-progress --memory-limit=-1` and capture the current error list as the story's working baseline (AC: #1, #2)
- [ ] Fix `Modules/User` errors file by file: explicit param/return types, `Builder<Model>`/`Collection<int, Model>` generics, nullable-safe access (AC: #1, #3)
- [ ] Fix `Modules/Lang` errors file by file using the same approach (AC: #2, #3)
- [ ] For each accessor touched while fixing types, verify or add the `get{X}()` twin method (AC: #4)
- [ ] Re-run `./vendor/bin/phpstan analyse Modules/User Modules/Lang --no-progress` and confirm exit 0 (AC: #1, #2)
- [ ] Run `git diff --stat laravel/phpstan.neon` and confirm no output (AC: #5)

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

- **Requirement driving this story:** NFR-CQ-001 states the target as "PHPStan Level 10 (0 errors), all 35 modules... Current: 28/35 modules pass (174 errors in User, Lang, etc.)... Deadline: Week 10... Enforcement: CI gate blocks merge if PHPStan L10 fails." [Source: prd.md#NFR-CQ-001]
- **Architecture grounding:** ADR-008 ("Standardize Module, Model, Table, and Filament Naming") directs "shared base behavior in Xot base classes instead of per-module copies": where `User`/`Lang` type errors stem from duplicated base-model logic rather than module-specific code, prefer resolving via the shared `Xot` base class over a local per-module fix. [Source: architecture.md#adr-008]
- **phpstan.neon is immutable by agents:** "Unico file di config PHPStan del progetto: `laravel/phpstan.neon`... Solo l'UTENTE umano può modificarlo. Gli agenti AI mai, nemmeno per 'ripristino', 'debug', 'temporaneo'... Il livello è sempre quello massimo già definito nel config root: gli agenti non passano `--level` e non abbassano mai il livello." No `phpstan-*.neon` files, no `ignoreErrors`/baseline entries added by the dev agent. [Source: docs/wiki/rules/phpstan-neon-immutable.md]
- **Accessor/twin convention:** "Dentro l'accessor `$this->attributes['colonna'] ?? null` sempre guardato e col nome reale della colonna." Verification command: `php artisan xot:check-accessor-twins --module=User --fail-on-missing` (and `--module=Lang`). [Source: docs/wiki/rules/accessor-twin-method.md]
- [Inference] The PRD gives only the aggregate error count (174, across User/Lang/others) as of the PRD's writing date, not a per-module or per-file breakdown. The dev agent must treat the Task #1 baseline run as the authoritative current error list: do not assume the PRD's historical count still matches the live codebase.
- [Inference] "Type debt" in this story is understood as PHPStan-flagged typing errors only (missing types, incorrect generics, unsafe nullable access): not a request to refactor business logic, rename methods, or change public API surfaces. Any fix that would change a method's external behavior is out of scope and should be flagged rather than made.

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- **Test type:** Static analysis (PHPStan CLI run), not unit/feature tests. A secondary Artisan command check (`xot:check-accessor-twins`) validates AC #4.
- **Scenarios to prove each AC:**
  - AC #1/#2: run PHPStan against `Modules/User` and `Modules/Lang` independently; each must report "[OK] No errors" (exit code 0).
  - AC #3: manual review of the diff: no new `@phpstan-ignore-line`, no `mixed` left where a concrete type is inferable from the surrounding code (e.g. Eloquent relation return types, Spatie permission trait method stubs).
  - AC #4: run the accessor-twin checker for both modules with `--fail-on-missing`; must exit clean.
  - AC #5: `git diff --stat laravel/phpstan.neon` must produce no output.
- **Fixtures/mocks:** none required: this is a static-analysis-only story, no runtime test doubles needed.
- **Edge cases to cover:** Spatie `HasRoles`/`HasPermissions` trait methods not natively understood by PHPStan (may need `@mixin` PHPDoc, not runtime code changes); circular type references between `User` and `Lang` models if any relation exists between them; generic collection typing on paginated Filament table queries.
