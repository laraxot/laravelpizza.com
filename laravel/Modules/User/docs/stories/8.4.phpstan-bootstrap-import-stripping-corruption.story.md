## Contesto

Richiesta utente: eseguire `phpstan analyse Modules`, analizzare e sistemare TUTTE le segnalazioni, coordinandosi con altri agenti AI concorrenti sullo stesso repository (lavoro multi-agente attivo), senza mai fermarsi.

PHPStan/Larastan effettua il bootstrap completo dell'applicazione Laravel (tutti i service provider, tutti i moduli) prima di analizzare qualsiasi path. Un singolo file PHP con sintassi/riferimenti rotti in QUALSIASI punto dell'albero blocca l'intera analisi, indipendentemente dal path passato a `analyse`.

## Problema riscontrato

Durante tentativi ripetuti di ottenere un run pulito (9 tentativi consecutivi), ogni run falliva su un file diverso in `Modules/User`, tutti con la stessa firma: righe `use ...;` rimosse dal blocco import, mentre il corpo della classe continuava a referenziare quei nomi non qualificati (es. `XotBaseEditRecord`, `EditRecord`, `HasFiltersForm`, `ViewAction`, `DeleteAction`). Risultato: `Application bootstrap failed` / `PHP Fatal error: Class|Interface|Trait "..." not found`.

Ulteriore istanza trovata a run 9 (corpo gia' pulito prima della mia lettura, corretto da altro agente durante l'esecuzione stessa del run):
- `app/Actions/User/UpdateUserAction.php` (trait `Spatie\QueueableAction\QueueableAction` non trovato al momento del crash, file gia' corretto quando controllato: race con agente concorrente)

File corrotti trovati e riparati in questa sessione:
- `app/Filament/Resources/SocialProviderResource/Pages/EditSocialProvider.php`
- `app/Filament/Resources/TeamResource/Pages/EditTeam.php` (auto-riparato da altro agente concorrente prima del mio intervento)
- `app/Filament/Resources/UserResource/Pages/BaseListUsers.php`
- `app/Filament/Resources/UserResource/Pages/BaseEditUser.php`
- `app/Filament/Resources/UserResource/Pages/ViewUser.php` (corpo classe parzialmente troncato, non solo import)
- `app/Filament/Resources/TenantResource/Pages/EditTenant.php` (auto-riparato da altro agente concorrente)
- `app/Listeners/LogoutListener.php`
- `app/Http/Livewire/Auth/Register.php`
- `app/Filament/Resources/TeamResource/RelationManagers/UsersRelationManager.php`

## Metodo di riparazione

Per ogni file: `git show HEAD:<path>` per ottenere la versione corretta, confronto diff con `diff <(git show HEAD:path) path` per confermare che la differenza sia limitata a righe `use` (o corpo troncato coerente con HEAD), poi ripristino tramite `Write`/`Edit` (mai `git checkout --`, per policy). Ogni file verificato con `php -l` dopo la modifica.

**Attenzione: falso positivo scoperto**: non tutte le rimozioni di `use` sono corruzione. `Modules/Cms/app/Filament/Resources/PageContentResource.php` e `SectionResource.php` avevano import rimossi ma NON più referenziati nel corpo: pulizia legittima dello swarm Epic-4 (estrazione inline form/table verso classi `Schemas/`). Questi due file sono stati lasciati intatti. Dettaglio del metodo di distinzione in memoria: `pattern_import_stripping_corruption_vs_legit_cleanup.md`.

## Stato

- Scansione mirata (diff-only-su-use, con verifica riferimento nel corpo) eseguita due volte sull'intero albero `Modules/`: alla seconda passata restano solo i 2 falsi positivi legittimi sopra citati, nessun altro file con pattern di corruzione pura da import.
- Run phpstan full-tree tentati: 9 consecutivi falliti sul bootstrap fino a questa sessione, causa cambiamenti concorrenti di altri agenti su `Modules/User`. Non ancora ottenuto un run completo con JSON di errori popolato.
- Prossimo passo: continuare a rilanciare il full-tree run finché il bootstrap non supera la fase di discovery, poi costruire la worklist reale per-modulo/per-errore.
