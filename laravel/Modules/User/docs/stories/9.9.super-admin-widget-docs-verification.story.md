## Esito: icone SuperAdminWidget

Stato su disco (convergenza post-race documentata in 9.7):
`x-filament::icon-button` + `icon="user-superman"` / `icon="user-clark-kent"`,
SVG in `resources/svg/` auto-registrati da `XotBaseServiceProvider::registerBladeIcons()`
(prefix `user` → `user-superman` risolve `superman.svg`).

Verifiche eseguite in questa sessione (tinker, app reale):
- `svg('user-superman')` → `BladeUI\Icons\Svg`, markup completo e non vuoto.
- `Blade::render('<x-filament::icon-button icon="user-superman" ...>')` →
  `<svg class="fi-icon fi-size-md">` inline corretto.
- CSS compilato `public_html/css/filament/filament/app.css`: regole `.fi-icon`,
  `.fi-icon.fi-size-sm`, `.fi-icon-btn` presenti → icona dimensionata e colorata.

**Root cause residua individuata** (non ancora corretta: file sotto lock di
sessione concorrente `cursor-grok`, task `user-9.8-icons`, lock 18:00):
la vista renderizza l'icona SOLO se `isSuperAdmin()` OR `isNegateSuperAdmin()`.
Un utente con NESSUNO dei due ruoli ottiene `<span>` vuota → widget
"invisibile". Se la segnalazione "icone non si vedono" arriva da un utente
senza quei ruoli, il fix e' un ramo `@else` (es. clark-kent `color="gray"`,
tooltip `tooltip.inactive`) in `super-admin.blade.php`: da coordinare con la
sessione che detiene i lock, non applicato qui per non violarli.
