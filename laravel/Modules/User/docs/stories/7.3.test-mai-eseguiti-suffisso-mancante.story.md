# 7.3: due test di User non venivano eseguiti da nessuno

**Status:** done: **Created:** 2026-08-27

## Il difetto

`Modules/User/phpunit.xml` seleziona i test così:

```xml
<directory suffix="Test.php">./tests</directory>
```

Un file sotto `tests/` che chiama `test(...)` o `it(...)` ma **non** finisce in
`Test.php` non viene caricato da nessuno. PHPStan lo analizza: e conta i suoi errori -
mentre il runner non lo vede: protezione zero, rumore pieno.

| File | Diagnosi | Azione |
|---|---|---|
| `tests/Feature/user-management-business-logic.php` | duplicato di `UserManagementBusinessLogicTest.php`, **zero righe proprie** su 407 | rimosso |
| `tests/Feature/Passport/ClientCredentials.php` | **nessun gemello**: 74 righe di test veri, mai eseguiti dal giorno in cui sono stati scritti | rinominato `ClientCredentialsTest.php` |

**Senza gemello non è un duplicato.** `ClientCredentials.php` non andava cancellato:
andava fatto girare. Rinominarlo alza il coverage senza scrivere una riga nuova.

Esito del test riportato in vita, misurato: **2 test scoperti, entrambi `skipped`** con
motivo esplicito («DB `user` non disponibile in ambiente test condiviso»). Prima non
erano né eseguiti né saltati: erano invisibili. Ora entrano nel conteggio e gireranno
appena il database dedicato c'è.

## Non era un caso isolato

Stesso difetto trovato oggi cinque volte:

| Modulo | File |
|---|---|
| Notify | `emailtemplatestest.php`, `jsoncomponentstest.php` |
| Xot | `metatagdatatest.php` |
| User | `user-management-business-logic.php`, `Passport/ClientCredentials.php` |

## Il gate

Nessuna delle regole toccate oggi aveva un controllo eseguibile. Aggiunte a
`bashscripts/quality-gates/audit-module-theme-root-files.sh`:

- **test mai eseguiti**: cerca sotto `laravel/Modules/*/tests` e `laravel/Themes/*/tests`
  i `.php` che contengono `^\s*(test|it)\(` e non finiscono in `Test.php`. Le fixture
  (`DummyTestModel.php`, `HasTableWithXotTestClass.php`) non contengono chiamate Pest e
  restano fuori: il discriminante è la chiamata, non il percorso;
- **cartelle MAIUSCOLE** nelle root di modulo/tema (Rule 1 di
  `module-theme-root-cleanup.md`), oggi a zero violazioni;
- **unicità del `.code-workspace`** (Rule 2), già introdotta nella story 9.2 di Xot.

## Acceptance Criteria

1. Nessun file sotto `tests/` contiene chiamate Pest senza finire in `Test.php`.
2. Nessun contenuto di test perso: il file senza gemello è rinominato, non rimosso.
3. Il gate verifica la regola ed esce diverso da zero sulle violazioni.
4. `phpstan analyse Modules/User` resta a zero.

## Verifiche

- `bash bashscripts/quality-gates/audit-module-theme-root-files.sh` → 21 moduli/temi, **0 violazioni, PASS**.
- `phpstan analyse Modules/User` → `[OK] No errors`.
- `phpmd` sul file rinominato → nessuna segnalazione.
- `php -l` sul file rinominato → ok.

## Avvertenza sulla misura PHPStan di oggi

Mentre questa story veniva chiusa, **3 processi PHPStan giravano con `-c <neon custom>`**
che disattiva larastan e il plugin Pest e scrive nella cache condivisa `/tmp/phpstan`.
Finché succede, ogni «zero» va considerato non verificato: vedi
`docs/chat/STOP-cache-phpstan-avvelenata-da-config-custom.md`.
