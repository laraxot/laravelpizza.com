# Gdpr — PHPStan level max fix

Riferimenti correlati: `Modules/Gdpr/docs/stories/phpstan-Gdpr-fix.md`,
`Modules/Gdpr/docs/stories/gdpr-mixed-type-reduction.story.md`,
`Modules/Xot/docs/stories/18.12.gdpr-phpstan-l10-fix.story.md` (story precedente
piazzata per errore in Xot da uno swarm precedente; questa story nel modulo owner
la sostituisce/aggiorna, non la cancella).

## Problema

Baseline (`./vendor/bin/phpstan analyse Modules/Gdpr --memory-limit=-1`, cache pulita):
**4 errori**:

1. `app/Models/Traits/HasGdpr.php:66,81,169` — `Cannot cast mixed to string`
   (`cast.string`): `(string) $this->getKey()` — `Model::getKey()` è tipizzato
   `@return mixed` in Eloquent; il cast diretto a stringa è genuinamente non
   sicuro (una chiave primaria composita/oggetto romperebbe la cache key senza
   errore visibile).
2. `tests/PestHelpers.php:24` — `ignore.unmatchedLine (non-ignorable)`: un
   `@phpstan-ignore-next-line` residuo su `$test = test();` non copriva più
   nessun errore reale (falso positivo storico, ormai risolto dagli stub Pest).

Durante il fix, la rimozione di un `@var` illegittimo (vietato dalle regole
PHPStan del progetto: "Do not use assert() or inline @var PHPDoc tag to
override PHPStan's inferred type") ha fatto emergere un **quinto errore reale
preesistente e mascherato**:

3. `app/Models/Traits/HasGdpr.php` (`getMissingRequiredConsents()`) —
   `array_diff()` riceveva `array<mixed>` da
   `$this->activeConsents()->pluck('type')->toArray()` dietro un `@var
   array<string>` che nascondeva il tipo reale inferito da PHPStan
   (`argument.type`).

## Solution

- Introdotti due metodi `protected` riutilizzabili in `HasGdpr`:
  - `gdprKeyAsString(): string` — narrowing esplicito di `getKey()` (mixed) a
    `string|int` via `match(true)`, con `RuntimeException` per tipi di chiave
    non supportati (nessun cast silenzioso, nessun `@phpstan-ignore`).
  - `gdprConsentCacheKey(string $type): string` — costruisce la cache key
    riusando `gdprKeyAsString()`, eliminando la duplicazione presente in 3
    punti (`hasGivenConsent`, `hasGivenConsentWithoutCache`,
    `clearConsentCache`).
- `getMissingRequiredConsents()`: sostituito l'`@var` illegittimo con un
  `foreach` + `is_string()` che filtra realmente i valori non stringa
  restituiti da `pluck('type')`, invece di dichiarare per decreto un tipo che
  PHPStan non poteva verificare.
- `tests/PestHelpers.php`: rimosso il commento `@phpstan-ignore-next-line`
  morto su `gdprTest()` (riga 23); il secondo ignore (su
  `HigherOrderTapProxy`) resta, verificato ancora necessario.
- `phpunit.xml`: `bootstrap="vendor/autoload.php"` era rotto (il modulo non ha
  un proprio `vendor/` in questo monorepo) — corretto in
  `bootstrap="../../vendor/autoload.php"`, allineato al pattern già usato da
  Notify/Xot/UI/Lang/Tenant. Senza questo fix `./vendor/bin/pest -c
  Modules/Gdpr/phpunit.xml` non parte affatto ("Cannot open bootstrap
  script").
- Aggiunti test unitari in `tests/Unit/Traits/HasGdprTraitTest.php` che
  esercitano via Reflection i due nuovi metodi (`gdprConsentCacheKey` con id
  stringa e id intero, `gdprKeyAsString` con tipo di chiave non supportato →
  `RuntimeException`), senza toccare il DB (i metodi leggono solo l'attributo
  `id` in memoria sulla fixture `HasGdprDummy`).

Nessuna modifica a `phpstan.neon` (di proprietà utente, non toccato). Nessun
nuovo `@phpstan-ignore`.

## Acceptance criteria

- [x] `./vendor/bin/phpstan analyse Modules/Gdpr --memory-limit=-1` → 0 errori

- [x] Pest: nuovi test aggiunti per i metodi introdotti; coverage del trait
      non diminuita (vedi `docs/coverage.md`).
- [x] Git sync sul remote reale del modulo (`laraxot`), senza force-push.

## Note per chi riprende questa story

- Il modulo condivide `tests/Pest.php` root del monorepo, che fa `glob()` su
  `Modules/*/tests/Pest.php` e (indirettamente, via bootstrap) su tutti i
  `PestHelpers.php` degli altri moduli: un altro modulo con un file PHP rotto
  a metà edit blocca *tutti* i Pest run, incluso quello scoped a Gdpr. Non è
  un bug di questa story; se càpita, verificare con `php -l
  Modules/*/tests/Pest.php Modules/*/tests/PestHelpers.php` e ritentare.
