# 4.30: module_notify_fila5 remote git object corruption

## Story

As a maintainer, I want the `module_notify_fila5` GitHub remote's missing commit object restored,
so that local commits (already correct, already fixing today's PHPStan zero campaign work) can
finally push to `laraxot/dev`.

## Root Cause (verified on code, not docs, 2026-09-06/07)

- `git push laraxot dev` from `laravel/Modules/Notify` fails: `Could not read
  2c641c73c5ab1282c044f3436ac2573cb73d28e0` / `remote unpack failed`.
- `git fsck --full` shows it's a missing parent of commit `84e1d920` (2026-09-06 21:51): that
  commit's own message already notes "[graft: broken parent 2c641c73 missing upstream, treated as
  root - local-only replace, not pushed]", meaning a prior session already found this and worked
  around it locally with `git replace` (see `git replace -l`).
- Confirmed broken on the remote too, not just local clones: `git fetch laraxot
  2c641c73c5ab1282c044f3436ac2573cb73d28e0` (direct targeted fetch) returns `fatal: bad object` /
  `did not send all necessary objects`: GitHub's copy is genuinely missing that object.
- Same failure shape independently hit `module_user_fila5` the same day (missing object
  `c7892391...`): see `8.1.module-remote-git-object-corruption.story.md`. Two independent modules
  hitting the exact same symptom is a pattern worth escalating together.
- Note: this is a DIFFERENT issue from `4.25.git-conflict-marker-remediation.story.md` (an older,
  2026-09-03 unrelated-history merge with literal conflict markers): don't conflate the two.

## What NOT to do

- No `git reset --hard`, no `revert`, no `gc`, no history rewrite.
- Don't re-run the same diagnostic commands session after session: already documented in
  `docs/chat/notify-remote-git-corruption-blocking-push.md` and second-brain memory
  `project_notify_remote_git_corruption_2026_09_07.md`.
