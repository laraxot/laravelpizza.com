# 4.31: swarm phpstan 2026-09-15: 2 errori riportati, 0 trovati

## Contesto

Sessione swarm multi-agente sul fix PHPStan fleet-wide (4 moduli assegnati:
Performance, IndennitaResponsabilita, IndennitaCondizioniLavoro, Notify). A meta'
task il coordinatore ha rilevato collisione con un'altra sessione gia' attiva su
Performance/IndennitaResponsabilita e ha ristretto questo subagent a **solo
IndennitaCondizioniLavoro e Notify**. Vedi la story gemella in
`Modules/IndennitaCondizioniLavoro/docs/stories/7.2...` per il dettaglio del
blocco fleet-wide incontrato durante l'indagine (fatal `Cannot override final
method getTableColumns()` in un file Ptv, non nello scope di questo subagent,
risolto da un altro agente durante la sessione).

Report di partenza (`Notify.txt`, generato lo stesso giorno): 2 errori in
`tests/Feature/ThemeManagementBusinessLogicTest.php:15` -
`it('theme management tests are skipped')->skip('Theme model not implemented');`
- diagnosticati come `method.nonObject` ("Cannot call method skip() on null") e
`function.void` ("Result of function ... it (void) is used").

## Causa

Stesso pattern documentato in `bashscripts/ai/wiki/rules/pest-phpstan-bridge.md`:
un bridge Pest scritto a mano (rimosso il 24 agosto 2026) ridichiarava le funzioni
globali Pest con firma `: void`. La fix verificata a monte e' l'attivazione di
`pestphp/pest-plugin-phpstan` via `phpstan/extension-installer` (automatica,
`phpstan.neon` non tocca gli `includes`: verificato non modificato). Il report
odierno risultava da una misura precedente al riassestamento della fleet (blocco
Ptv + eventuale cache `/tmp/phpstan` condivisa non fresca).

Misura di questa sessione, `tmpDir` isolata e privata:

```
cd laravel && php -d memory_limit=-1 ./vendor/bin/phpstan analyse \
  -c <scratch>/phpstan-isolated-icl-notify.neon Modules/Notify --no-progress
[OK] No errors
```

`php -l` pulito sul file. Nessuna modifica di codice necessaria: **nessun file
toccato in questo modulo**.
