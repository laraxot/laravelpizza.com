# Consolidate Email Module into Notify as Channel Provider

## Objective

Eliminate Email as standalone module. Migrate email sending capabilities into Notify as a channel provider (alongside SMS, WhatsApp). Make Notify the single source of truth for all notification delivery.

## Context

**Current State:**
- Email module: sends emails, templates, retry logic
- Notify module: orchestrates multi-channel notifications (email, SMS, WhatsApp), versioned templates
- **Duplication:** Both handle templates, retries, delivery logging
- **Confusion:** Modules import Email directly instead of routing through Notify

**Problem:**
- Two parallel notification systems (Email direct, Notify orchestrated)
- Template management scattered (Email templates, Notify templates)
- New channel requires changes in Email + Notify
- Tight coupling to email provider in domain modules

**Solution:**
1. Move Email sending logic into Notify's `Channels/EmailChannel.php`
2. Register email provider in Notify's channel registry
3. Deprecate Email module (mark for removal)
4. Migrate all email imports to Notify

## Deliverables

### 1. Email Channel Implementation in Notify (Phase 1)

Create `Modules/Notify/app/Channels/EmailChannel.php`:

```php
namespace Modules\Notify\Channels;

class EmailChannel implements NotificationChannelContract {
    public function send(Notification $notification): DeliveryResult {
        $mail = Mail::mailable($notification->mailable());
        $result = $mail->send();
        return new DeliveryResult($result->success());
    }
    
    public function canRetry(DeliveryAttempt $attempt): bool {
        return in_array($attempt->error_code, [
            'smtp_timeout', 'auth_failure', 'rate_limit'
        ]);
    }
}
```

**Responsibilities:**
- Send email via Laravel Mail façade
- Handle SMTP errors with retry logic
- Log delivery attempts
- Support templates from Notify's template registry

### 2. Migrate Email Templates to Notify (Phase 1)

Move email template definitions from `Email::MailTemplate` to `Notify::MailTemplate`:

```php
// Move from Email module
class MailTemplate extends Sushi {
    protected $filePath = 'database/content/mail-templates.json';
}

// Register in Notify's template registry
app(MailTemplateRegistry::class)->register('invoice-sent', InvoiceSentMail::class);
```

### 3. Update Notify Channel Registry (Phase 1)

Register EmailChannel in `Modules/Notify/app/Providers/NotifyServiceProvider.php`:

```php
app(ChannelRegistry::class)->register('email', EmailChannel::class);
```

Notify already supports multi-channel; EmailChannel is just another provider:
```php
app(Notify::class)
    ->channel('email')
    ->send($notification);
```

### 4. Deprecate Email Module (Phase 2)

Update Email's ServiceProvider:
```php
// Mark as deprecated
public function register(): void {
    // Redirect all imports to Notify
    $this->app->bind(EmailService::class, fn() => new EmailDeprecationProxy());
}
```

Add deprecation warning in README.md:
```
⚠️ **Deprecated:** Email module is deprecated. Use Notify module instead.

Migrate:
- `Mail::mailable()` → `app(Notify::class)->channel('email')->send()`
- Email templates → Notify templates
```

### 5. Test EmailChannel (Phase 1)

Create `Modules/Notify/tests/Feature/Channels/EmailChannelTest.php`:

- Log delivery attempt with timestamp
- Support template variables
- Error handling (auth failure, missing recipient)

## Related Issues & Decisions

**Design Decision:** EmailChannel is a Notify provider, not a merged module

- **Rationale:** Notify already has channel abstraction (SMS, WhatsApp); Email is just another channel
- **Alternative:** Merge Email directly into Notify codebase
- **Decision:** Use existing Notify architecture; EmailChannel plugs into channel registry

**Design Decision:** Keep Email module for Phase 2 deprecation

- **Rationale:** Soft migration: email works through Notify first, then Email module can be removed
- **Alternative:** Delete Email module immediately
- **Decision:** Deprecate with warnings, remove in separate story

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| SMTP config conflicts | EmailChannel uses standard Laravel config `config('mail.*')` |
| Template variable clash | Namespace email templates as `email::*` in Notify registry |
| Delivery logging incompatibility | Log format unified: use Notify's DeliveryAttempt model |
| Backward compatibility | Email module stays functional; migration is gradual |
