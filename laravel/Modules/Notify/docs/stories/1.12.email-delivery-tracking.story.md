# 1.12: Email Delivery Tracking (Bounce Log, Retry Logic)

**Story ID:** 1.12
**Epic:** 1: Scheda Management Workflows
**Slug:** email-delivery-tracking
**Status:** backlog

## Story

As an HR admin,
I want every Scheda email send attempt logged with automatic retries on failure,
so that delivery problems are visible and self-heal without manual intervention, supporting the 99.5% deliverability target.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Every send attempt made by Story 1.2's `SendSchedaEmailJob` is recorded as a delivery-log entry (`scheda_id`, `attempt_number`, `status`, `timestamp`).
2. On a hard bounce or send failure, the system retries automatically up to 3 attempts spread over 24 hours before giving up.
3. After the 3rd failed attempt, the Scheda's delivery status is marked `failed` and no further automatic retries occur.
4. `Scheda.bounced_at` is set when a bounce is recorded (via a provider webhook if configured, or via job-side hard-failure detection if no webhook is configured).
5. hr_admin can view a delivery-log list (per Scheda) showing attempt history and current status.

## Tasks / Subtasks

- [ ] Create `SchedaEmailDelivery` model + migration (`scheda_id`, `attempt_number`, `status`, `error_message`, `created_at`) (AC: #1)
- [ ] Record a delivery-log entry on every attempt inside `SendSchedaEmailJob` (from Story 1.2) (AC: #1)
- [ ] Configure job retry backoff: 3 attempts spread across 24h (Laravel queue `backoff()`/`tries`) (AC: #2)
- [ ] On the final failed attempt, mark the Scheda's delivery status `failed` (AC: #3)
- [ ] Add a `bounced_at` migration on `schedas`; set it on detected bounce (webhook listener or job-side hard-failure check) (AC: #4)
- [ ] Build a delivery-log Filament relation manager listing `SchedaEmailDelivery` entries (AC: #5)
- [ ] Feature tests: successful send records one entry; forced failures record 3 attempts then stop; `bounced_at` set on bounce; delivery-log page lists entries (AC: #1-#5)

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- **Feature:** `Queue::fake()`/a forced-failure mail transport double simulates 3 retry attempts across the configured backoff schedule; assert exactly 3 `SchedaEmailDelivery` rows and the Scheda marked `failed` after the 3rd attempt; assert only 1 delivery row on first-attempt success; simulate a bounce via a direct call to the bounce-handling path (a live provider webhook is not testable in CI) and assert `bounced_at` set.
- **Unit:** backoff-schedule configuration produces attempts spread across ~24h (assert configured intervals, not real elapsed time).
- **Fixtures:** a fake mailer/transport double toggleable to fail N times then succeed, or always fail, for deterministic retry-count assertions.
- **Edge cases:** job succeeds on the 2nd attempt (1 failure + 1 success recorded, no 3rd attempt fired); delivery-log view for a never-sent Scheda shows an empty state.
