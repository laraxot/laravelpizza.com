# 4.25: Git conflict marker remediation: Notify

## Story

As a maintainer running `phpstan analyse Modules`, I want the Notify module's committed git conflict
markers removed with the architecturally-correct side chosen per hunk, so that the whole-repo PHPStan
bootstrap stops crashing on a PHP parse error and Notify code depends on Xot contracts instead of a
hard cross-module dependency on TechPlanner.

## Root Cause (verified on code, not docs)

- `laravel/Modules/Notify` HEAD (`52abdac1`) is a merge commit (`Merge: f9d10a8e dc3a77b1`) of two
  commit graphs with **no common ancestor** (`git merge-base f9d10a8e dc3a77b1` returns nothing;
  `git rev-list f9d10a8e ^dc3a77b1` = 214, the reverse = 14: i.e. fully unrelated histories, not a
  normal divergence). The merge was committed with **literal `<<<<<<<`/`=======`/`>>>>>>>` markers
  left inline** instead of being resolved: this is what crashes `Filament\Panel->discoverComponents()`
  during PHPStan/Larastan bootstrap (`unexpected token "<<"`).
- Parent `f9d10a8e` (5 commits, local-only, never pushed) is 100% clean: verified 0 marker files
  across all 729 tracked `.php` at that commit.
- Scope at HEAD: 143 `.php` files, 410 conflict blocks. `docs/CLAUDE.md` (and likely other `.md`) also
  carries markers: out of scope for this story (PHP-only, unblocks bootstrap); tracked as follow-up.
- Per `git-forward-only` rule: no `reset`/`revert`/`checkout` of the bad merge. Resolution is a new
  forward patch on the current tree.

## Acceptance Criteria

<!-- LOCKED -->
1. Zero `<<<<<<<`/`=======`/`>>>>>>>` markers remain in any `Modules/Notify/**/*.php` file.
2. Every hunk resolved by reading both sides (`ours` = HEAD, `theirs` = `laraxot/dev`) and picking the
   version that matches current, verified project architecture: not a blind "ours always wins":
   - `Modules\Xot\Contracts\ProfileContract` wins over `Modules\TechPlanner\Models\Profile` in Models'
     `use` imports and `@property-read` PHPDoc (Gdpr/Geo modules already depend on the same Contract;
     a generic module hard-depending on the tenant-specific `TechPlanner` model breaks module
     independence: [[module-independence]]).
   - `getFormSchema()` (with active `#[Override]`) wins over `getFormSchemaOld()` in Resource classes
     and their test callers: `getFormSchemaOld` is XotBaseResource's legacy/dead alias.
   - Style-only hunks (parens on `new X()`/`new X`, whitespace) resolved deterministically, then
     normalized by `./vendor/bin/pint` (`new_with_parentheses` per `pint.json`).
   - Any hunk that is a genuine behavioural fork with no way to determine correctness from current
     source (base classes, sibling call sites) is resolved to keep the working/current (`ours`) side
     and flagged explicitly in this story's Dev Notes for a human follow-up: not guessed silently.
3. `php -l` passes on every touched file; `composer dev` / `phpstan analyse Modules` no longer fails
   at the bootstrap stage (Application bootstrap failed / "<<" parse error) for Notify.
4. `./vendor/bin/pint` run on touched files only (not the whole module) to avoid unrelated churn.
5. `./vendor/bin/pest` for Notify passes (or pre-existing failures unrelated to this story are listed,
   not silently introduced): this story does not fix `4.23` PHPStan findings, only the parser-crash.
6. Coverage doc (`Modules/Notify/docs/coverage.md`) untouched unless this story's changes shift it -
   record actual numbers, not guessed ones.
7. New commit(s) only: no `git reset --hard`, no branch rewrite. `laraxot/dev`'s remaining 216
   commits / unrelated history reconciliation is explicitly OUT of scope (human decision, per
   [[feedback-bulk-conflict-resolution]]).

- Ground truth for `ProfileContract`: `Modules/Xot/app/Contracts/ProfileContract.php` exists and is
  already consumed by `Modules/Gdpr` and `Modules/Geo` models: confirms it's the established pattern,
  not a one-off.

  both `getFormSchema()` (line ~141) and `getFormSchemaOld()` (line ~161, legacy). `ContactResource`,
  `MailTemplateResource`, `NotificationResource` (not conflicted) already override `getFormSchema()`
  directly: confirms `NotifyThemeResource`/`NotificationTemplateResource` should match, not diverge.
- Auto-resolution script logic (for the record, not re-run blindly): normalize `new X()`/`new X` and
  whitespace: if the two sides are equal after normalization keep the parenthesized form (project Pint
  rule); if one side is empty keep the non-empty side; if both sides are literally equal keep either.
  Left everything else untouched for hand/agent review.
- Do **not** touch `phpstan.neon` (owner: user only, [[phpstan-neon-user-only]]).
- Do **not** `git reset`/`revert`/`checkout`: [[git-forward-only]].
