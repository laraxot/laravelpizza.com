# Story 9.1: Deduplicate PSR-4 Class Files: Notify Module

**Status**: awaiting-analysis  
**Module**: Notify  
**Issue**: PSR-4 duplicate class files (from prior merge)  
**Effort**: small  
**Owned by**: TBD

## Problem

Prior session found **PSR-4 duplicate**: One test file contains 3 classes that already exist as separate files. This creates ambiguity in autoloading and violates single-responsibility principle.

**Reference**: Memory entry `notify-psr4-duplicate-2026-08-27`

## Workflow

1. **Locate duplicate**:
   ```bash
   grep -rn "class.*Test\|class.*Action" Modules/Notify/tests --include="*.php" | grep -E "^\s*class "
   ```

2. **Identify which file has 3 classes**:
   - Read that file
   - Note the 3 class names
   - Locate their "real" files (separate files)

3. **Decision**:
   - If 3 classes in combined file are tests: split into separate files per PSR-4
   - If combined file is newer/better: move other files to archive, keep combined
   - If different implementations: merge intelligently, choose best

4. **Fix**:
   - Either split or remove duplicates
   - Ensure each class has one canonical location
   - Update imports if needed

5. **Verify**:
   ```bash
   phpstan analyse Modules/Notify --no-progress
   grep -r "class.*Action\|class.*Test" Modules/Notify --include="*.php" | wc -l  # Count before/after
   pest Modules/Notify/tests -c Modules/Notify/phpunit.xml --no-coverage
   ```

6. **Git sync**

## Success Criteria

- One canonical location per class (no duplicates)
- PSR-4 compliant file structure
- PHPStan: parses without duplicate-class errors
- Pest: all pass
- Git: clean

## Notes

- Duplicate files often result from merge conflicts
- May be side effect of concurrent development
- Consider whether both implementations needed or merge them
