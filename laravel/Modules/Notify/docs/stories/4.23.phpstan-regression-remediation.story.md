# 4.23: PHPStan regression remediation: Notify

## Story

As a maintainer, I want Notify's Pest contracts and boundary values made explicit, so that notification tests are both type-safe and behavioural.

## Acceptance Criteria

<!-- LOCKED -->
1. All 121 test-owned findings are removed without suppressions, invented notification APIs, or cross-module edits.
2. Notification payloads and channel values are narrowed at boundaries; tests call real signatures and validate meaningful outcomes.
3. Tautological/coverage-only tests are deleted or rewritten, with disposition counts recorded.
4. The canonical full PHPStan run attributes zero findings to Notify with clean bootstrap/stderr.
5. Existing Notify testing/PHPStan docs are consolidated DRY with durable findings.

## Tasks / Subtasks

- [ ] Triage G60/B22/H10/E10/F5/D6/tail8 by real boundary contract (AC: #1, #2)
- [ ] Correct TestCase/bootstrap and retained notification/channel tests (AC: #1, #2)
- [ ] Rewrite/delete coverage-only assertions (AC: #3)
- [ ] Validate focused tests and global PHPStan (AC: #4)
- [ ] Update an existing Notify PHPStan/testing document instead of adding another duplicate (AC: #5)

## Testing

<!-- LOCKED -->
- **Approach:** retained unit/command/channel tests, targeted static feedback, then cold global analysis.
- **Per-AC verification:** AC1/2 diagnostics plus observable notification behaviour; AC3 inventory; AC4 global JSON; AC5 docs diff.
- **Fixtures:** typed notification/channel doubles and valid Data objects.
- **Edge cases:** empty destination, unsupported channel, safe-class/function failures, environment reads, bootstrap errors.
