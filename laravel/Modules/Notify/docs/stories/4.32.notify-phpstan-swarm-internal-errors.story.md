## Errori reali trovati e fix alla sorgente

Famiglia 1: concat nullable negli header auth (radice unica,
5 file gemelli `Datas/SMS/*`):

- Scopo: `getAuthHeaders()` costruisce `Authorization` da credenziali
  config che possono mancare (`?string`).
- Causa: `?string . string` senza `?? ''` (es.
  `base64_encode($this->account_sid.':'.$this->auth_token)`).
- Fix: `?? ''` esplicito su ogni operando nullable.
- File: `TwilioData.php`, `PlivoData.php`, `NexmoData.php`,
  `AgiletelecomData.php` (basic + api_key + oauth), `SmsFactorData.php`
  (`Bearer '.($this->token ?? '')`).
- Comportamento invariato a config presente; a config assente evita
  coercizione null implicita.

Famiglia 2: `mixed` da `trans()`/`config()` propagato a Spatie Data:

- `Datas/FirebaseNotificationData.php::fromType()`: `trans()` rende
  `mixed`; assegnato diretto a `title`/`body: string`. Fix: narrow con
  `is_string()` + fallback (`$type` / `''`).
- Scopo: title/body localizzati per push Firebase; fallback garantisce
  sempre stringa a `Data::from()`.

Famiglia 3: guardie morte / sempre-vere:

- `Emails/SpatieEmail.php::__construct()`: `if ($tpl !== null)` su
  `firstOrCreate()` (ritorna sempre Model). Fix: rimosso il ramo,
  `update()` diretto.
- `Actions/BuildMailMessageAction.php::decodeRichText()`: `is_string()`
  dopo `Safe\mb_convert_encoding()` (Safe garantisce `string`, lancia
  su errore). Fix: assegnazione diretta, ramo `''` morto rimosso.
  Nessun cambio runtime (prima tirava comunque l'eccezione Safe).

Famiglia 4: `mixed` verso API tipizzate:

- `Notifications/GenericNotification.php::toMail()`: `$line` è `mixed`
  da `data['additional_lines']` verso `MailMessage::line(string)`.
  Fix: `is_scalar()` + cast `(string)`.
- `Emails/SpatieEmail.php::getAttachmentFromData()`: closure
  `fn () => $attachment['data']` rendeva `mixed` a
  `Attachment::fromData()`; `pathinfo()` senza shape + `extension`
  non narrowata. Fix: `$content` string narrowata, closure con
  `: string`, shape `array{dirname?,basename?,extension?,filename?}`,
  `is_string($extension)` prima di `getMimeTypes()`.
- `Emails/SpatieEmail.php::getAttachmentFromPath()`: docblock
  `array<string,string>` impreciso + `@var` silenziatori. Fix:
  param shape `array{path: string, as?: string|null, mime?: string|null}`,
  narrowing `is_string` per `as`/`basename`/`mime`, rimossi `@var` inline.
- `Enums/WhatsAppDriverEnum.php::isSupported()`: `array_column()` su
  `self::cases()` (tipizzazione debole). Fix: `array_map(static fn
  (self $case): string => $case->value, ...)`: stesso risultato,
  tipi pieni.

Test (solo `Modules/Notify/tests/`):

- `tests/Unit/Actions/BuildMailMessageActionTest.php`: assert stale su
  import inesistente `Spatie\LaravelData\DataCollection` (la Action usa
  `array<int, AttachmentData>|null`, non DataCollection: già segnalato
  in story 01 ma il file risultava ancora con il vecchio assert).
  Fix: assert su `Modules\Notify\Datas\NotifyThemeData` (import reale).

## Duplicati NormalizePhoneNumberAction: verifica chiamanti, nessuna consolidazione

- `app/Actions/NormalizePhoneNumberAction.php` (`execute(?string): string`,
  E.164 generico, fallback +39, `SafeStringCastAction`): ha test dedicato
  (`tests/Unit/Actions/NormalizePhoneNumberActionTest.php`, nullable +
  namespace `Actions` asseriti) → viva.
- `app/Actions/SMS/NormalizePhoneNumberAction.php`
  (`execute(string): string`, gateway italiano: strip parentesi,
  `ltrim` zeri, prefisso 39): usata da `SendNetfunSMSAction`,
  `SendAgiletelecomSMSv1Action`, `SendAgiletelecomSMSv2Action`
  (stesso namespace, `app(...)` diretto) + test dedicato
  (`tests/Unit/Actions/SMS/NormalizePhoneNumberActionTest.php`) → viva.
- Firme incompatibili (nullable vs non-nullable), logica diversa,
  entrambe coperte da test: cancellarne una romperebbe chiamanti/test.
  Decisione: **nessuna consolidazione distruttiva**. Unificazione solo
  valutabile come delega futura (root → SMS con default country) in una
  story separata, mai come delete in questo swarm.

## Distinzione errori reali vs ambiente

- Reali (fix sopra): concat nullable, `mixed` trans/config/attachment,
  guardie sempre-vere, `array_column` debole, assert test stale.
- Ambiente (segnalati, non fixabili via codice): tutti i 12
  internal-error stub + `ReflectionIntersectionType`. Richiedono
  rigenerazione/aggiornamento `phpstan.phar` o `php-8-stubs` fuori scope
  (mai toccati `vendor/`/`phpstan.neon`); finché persistono, PHPStan non
  può certificare questi file e può nascondere ulteriori finding reali.
