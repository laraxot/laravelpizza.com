# 1.7: Export Scheda to PDF

**Story ID:** 1.7
**Epic:** 1: Scheda Management Workflows
**Slug:** export-scheda-pdf
**Status:** backlog

## Story

As an evaluator or HR admin,
I want to download a single Scheda as a PDF directly from the resource list,
so that I can share or archive a copy without sending an email.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. From `SchedaResource`, an evaluator/hr_admin can trigger "Export PDF" on a single Scheda and download a PDF file directly (no email sent).
2. The exported PDF uses the same content/layout as the PDF generated for email in Story 1.2 (employee name, evaluation_type, year, scores, evaluator name, date, signature placeholder).
3. The export action is available regardless of status (draft, submitted, approved) but is hidden for soft-deleted records.
4. The download response filename follows the pattern `scheda-{employee_id}-{year}.pdf`.
5. Users below evaluator-level access cannot trigger the export (staff role denied at the resource-action level).

## Tasks / Subtasks

- [ ] Create `ExportSchedaPdfAction` reusing the `pdf/scheda.blade.php` view from Story 1.2 to stream a PDF response (AC: #1, #2, #4)
- [ ] Add "Export PDF" action on `SchedaResource` returning a file-download response (AC: #1, #3)
- [ ] Hide the action for trashed/soft-deleted records (AC: #3)
- [ ] Set the response filename per the naming pattern (AC: #4)
- [ ] Gate the action behind an evaluator-or-above policy check (AC: #5)
- [ ] Feature test: export streams a PDF with the correct filename/content-type; hidden for soft-deleted rows; denied for staff role (AC: #1-#5)

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

- [Source: prd.md#FR-002] PDF generation requirement (Laravel Snappy/wkhtmltopdf) and required content fields; this story reuses the same generation mechanism as Story 1.2 for a direct-download variant instead of an email attachment.
- [Source: architecture.md#component-design] Scheda Management component responsibility explicitly includes "exports."
- [Source: architecture.md#adr-005] queued jobs are the established pattern for PDF/email generation; [Inference] a single-record synchronous PDF render for direct download is small enough to serve inline within the HTTP request rather than queuing (unlike the bulk/retry-prone email path in 1.2/1.12). If generation time threatens the NFR-SC-001 p95 <500ms target, a follow-up story should move this to a queued-download-link pattern.

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- **Feature:** trigger export on a draft Scheda → response has `Content-Type: application/pdf` and `Content-Disposition` filename matching the pattern; trigger on a soft-deleted Scheda → action absent/403; trigger as a staff-role user → 403/action hidden.
- **Fixtures:** reuse `SchedaFactory` states from 1.1/1.2 (complete-scores draft, submitted, trashed).
- **Edge cases:** Scheda with partially-filled scores still exports (no completeness gate here, unlike the email-send action in 1.2): assert the PDF renders with blank/null score cells rather than erroring.
