# 19.1.Cms: marker del sync `laraxot/dev` in head/foot Blade e nei test

**Fase BMAD:** Dev/Review (risoluzione e verifica; nessun codice nuovo)
**Stato:** done

## Obiettivo

`phpstan analyse Modules` non parte finche' un file ha `<<<<<<<`/`>>>>>>>`. Il sync
`bashscripts/git/subtrees/merge_remote_repo_2.sh` (merge di `laraxot/dev`, poi `commit -am .`) li aveva
committati, fino a quattro livelli annidati. In `Cms` erano sette file: due Blade del front office e cinque
PHP di test. Le Blade sono `<head>` e coda del `<body>` di ogni pagina pubblica del tema Meetup
(`<x-cms::head>` in `Themes/Meetup/.../layouts/main.blade.php`): una merge sbagliata li' rompe tutto il sito.

## Risoluzione per file

| File | Scopo | Esito | Righe scartate |
|---|---|---|---|
| `resources/views/components/head.blade.php` | `<head>` pubblico: `@head`, CSS Filament solo se `$panelAssets`, CSS del tema via prop `$stylesheet`, stack `head` e `styles` | forma finale unica, coerente con `View\Components\Head` | blocco `<script>` del dark mode fuori dall'`@if ($panelAssets)` (copia vuota di Filament); due `@vite(['resources/css/app.css'])` fissi e un secondo `@filamentStyles`: il CSS arriva da `@vite([$stylesheet])` |
| `resources/views/components/foot.blade.php` | coda del body: notifiche e script Filament solo se `$panelAssets`, JS del tema, stack/yield `scripts` | versione con `@if ($panelAssets)`, `@see` nel commento Blade | la copia senza `@if` di `@livewire('notifications')`/`@filamentScripts`; tre `@see` e `--}}` duplicati |
| `tests/TestCase.php` | base dei test del modulo | un solo `use Modules\Xot\Tests\XotBaseTestCase;`, in ordine alfabetico; `@see ../testing.md` nel docblock | tre copie dell'import |
| `tests/Unit/Actions/Head/BuildHeadSchemaActionTest.php` | schema JSON-LD della home | `(new BuildHeadSchemaAction)` (stile Pint del repo) | `(new BuildHeadSchemaAction())`, solo stile |
| `tests/Unit/Http/Middleware/PageSlugMiddlewareFailClosedTest.php` | il 503 fail-closed del middleware di pagina | un solo blocco di `use`, in ordine | due copie degli stessi `Dcp283*Middleware` |
| `tests/Unit/Providers/FolioVoltSoleOwnerTest.php` | contratto: unico owner Folio e' `Cms\FolioVoltServiceProvider` | `use App\Providers\FolioServiceProvider` + `use Modules\Cms\Providers\FolioVoltServiceProvider` | FQCN inline `\App\...` e `\Modules\Cms\...` (Pint `fully_qualified_strict_types`) |
| `tests/Unit/Views/FilamentLayoutDirectivesTest.php` | guardia sul contratto Filament delle due Blade | docblock e regex `HEAD`: direttive dentro `@if ($panelAssets)`, `@vite([$stylesheet])`, assert su `@stack('head')`; percorso `dirname(__DIR__, 3)` (non avvia l'app) | testo «direttive sempre emesse» e regex con `@vite(['resources/css/app.css'])` fisso: contraddicono le Blade; variante `module_path()` (richiede l'app) |

La versione `6e32612c` delle due Blade non era un riferimento valido: `head` aveva il doppio `@vite` e `foot`
una riga `@see ... --}}` fuori da qualsiasi commento. Il riferimento e' stato il contratto, non lo snapshot.

## Scope

Solo i sette file elencati. `docs/bmad/filament-layout-styles-scripts.md` ha ancora marker (corsia dei `.md`).
