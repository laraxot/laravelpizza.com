# Story 6.1: Resolve Git Merge Conflicts + PHPStan Fixes — Cms Module

**Status**: ready-for-dev  
**Module**: Cms (independent .git)  
**PHPStan errors**: 16 (all parse-blocking merge conflicts)  
**Effort**: small  
**Owned by**: TBD (needs coordination)

## Problem

PHPStan bootstrap blocked by unresolved git merge conflicts in 3 files. All errors are `phpstan.parse` non-ignorable syntax errors from merge markers (`<<<<<<<`, `=======`, `>>>>>>>`).

## Affected Files

### 1. app/Filament/Forms/Components/DownloadAttachmentPlaceHolder.php
- Lines 11, 16, 20, 30 have merge markers
- Conflict between two implementations of placeholder logic
- **Action**: Keep simpler/cleaner version (right side usually)

### 2. tests/Feature/HomepageContentManagementTest.php
- Lines 130, 132, 135, 146, 148, 151, 169, 171, 174 have merge markers
- Multiple assertion blocks with conflicting implementations
- **Action**: Resolve each conflict by keeping version with better type safety

### 3. tests/Feature/Frontoffice/FolioRoutes/PublicProfileRouteTest.php
- Lines 19, 22, 27 have merge markers
- **Action**: Resolve conflicts (likely similar pattern to above)

## Solution

1. **Open each file** and manually resolve merge markers:
   - Remove `<<<<<<<`, `=======`, `>>>>>>>` markers
   - Choose one version (prefer right side = newer/safer)
   - OR merge both versions intelligently if complementary

2. **Verify syntax** after each file:
   ```bash
   php -l app/Filament/Forms/Components/DownloadAttachmentPlaceHolder.php
   php -l tests/Feature/HomepageContentManagementTest.php
   php -l tests/Feature/Frontoffice/FolioRoutes/PublicProfileRouteTest.php
   ```

3. **Run PHPStan** to verify:
   ```bash
   phpstan analyse Modules/Cms --no-progress
   ```

4. **Run Pest** (coverage check):
   ```bash
   pest Modules/Cms/tests -c Modules/Cms/phpunit.xml --no-coverage
   ```

5. **Git sync**:
   ```bash
   git add -A
   git commit -m "Cms: resolve git merge conflicts in tests + component"
   git fetch laraxot dev
   git merge laraxot/dev
   git push laraxot dev
   ```

## Success Criteria

- PHPStan: 0 parse errors
- All PHP files valid syntax (php -l)
- Pest: all pass
- Git: clean working tree, commits pushed

## Technical Notes

- Merge conflicts typically from concurrent feature branches
- No manual conflict resolution markers should remain in final code
- Both sides of conflict may have value — consider combining if non-overlapping
- Type safety preferred over feature completeness
