# Confine Cms

Cms possiede **Pages / Sections / Blocks**: è il candidato naturale per una
pagina `/sostieni` o `/collabora` e per una sezione «Partner e sostenitori»
proiettata nel footer — *dopo* il GO di governance. Oggi: solo documentazione.

## Perché Cms (business logic)

La sostenibilità si racconta con contenuti strutturati (chi sostiene, perché,
come contattare), non con codice nel dominio Ticket. Pages danno slug e
middleware; Sections riusano il blocco partner; Blocks restano vestiti dal tema.

## Responsabilità future (post-GO)

- Pagina dedicata: modello economico, uso fondi, elenco partner, CTA.
- Sezione riusabile per recognition nel footer (JSON SSoT, Blade = vestito).
- Workflow editoriale / approvazione contenuti partner (Blueprint Filament solo
  dopo Epic 1–2 BMAD).
- Nessun ad-server: asset locali via Media, no URL di terze parti traccianti.

## Non responsabilità

Pagamenti, policy legale partner, isolation tenant (→ Tenant), consenso
newsletter (→ Gdpr/Notify), rendering FO (→ Sixteen).
