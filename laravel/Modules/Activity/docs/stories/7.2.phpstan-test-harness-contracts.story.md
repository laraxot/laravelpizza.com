# Story ACTIVITY-7.2 — Contratti PHPStan dei test harness

## Story

Come maintainer Activity, voglio che fixture e test harness esprimano i contratti reali di
paginazione, autenticazione, Filament e mocking, affinché il gate statico distingua una
regressione di audit da un test che si limita a eseguire codice.

## Baseline e confine con ACTIVITY-7.1

La misura cold module-local del 24 agosto 2026 produce **39 findings in 11 file**, tutti
fuori dall'owned scope di ACTIVITY-7.1. La story 7.1 possiede Action, pagina applicativa e
due Feature test; questa story possiede esclusivamente fixture, TestCase e Unit test
elencati nel frontmatter. Chiudendo questi 39 findings, ACTIVITY-7.2 sblocca l'AC module-wide
di ACTIVITY-7.1.

XOT-5.28 è solo correlata: nessuno dei 39 findings è attribuito ai coverage harness Xot in
scope lì. Se durante lo sviluppo emerge una causa condivisa reale, il dev agent ferma il
file interessato e aggiorna la dependency map; non invade Xot.

## Root causes verificate

| Root cause | Findings | Contratto da ristabilire |
|---|---:|---|
| API Filament deprecate | 9 | testare la configurazione pubblica `table()`/schema, non i vecchi getter |
| mock e valori `mixed` usati come oggetti | 7 | creare intersezioni Mockery con il contratto/model reale e narrowing verificabile |
| API PHPUnit `groups()` interna | 4 | determinare DB/offline senza dipendere da API non-BC di PHPUnit |
| generics mancanti | 3 | specificare key/value di paginator e collection fixture |
| asserzioni tautologiche | 3 | sostituire con effetti osservabili o eliminare il test muto |
| return type più larghi del comportamento | 2 | dichiarare il tipo realmente restituito dalle fixture |
| funzioni non-safe | 2 | usare le varianti `Safe\` di `touch` |
| offset su configurazione `mixed` | 2 | validare la shape delle connection prima dell'accesso |
| argomenti incompatibili | 2 | usare `Authenticatable` reale e model mock tipizzato |
| tail: property only-written, return void, var tag, API/property inesistenti | 5 | correggere il contratto sorgente senza override PHPDoc |

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. I 39 findings della baseline sono risolti alla causa radice nei soli file owned e
   `phpstan analyse Modules/Activity` attribuisce zero findings ad Activity.
2. I fixture paginator/collection dichiarano generics reali; i mock che rappresentano
   Eloquent o autenticazione soddisfano i rispettivi contratti senza `mixed`, cast o
   `@var` usati per contraddire il tipo nativo.
3. `TestCase` preserva isolamento DB e gruppi `activity-db`/`no-activity-db` senza chiamare
   API PHPUnit `@internal`; configurazione e filesystem sono ristretti e Safe.
4. I test Filament osservano API pubbliche correnti. Nessun metodo protetto/deprecato è
   esposto o mantenuto solo per coverage e nessuna API immaginaria è introdotta.
5. Le tre asserzioni tautologiche sono riscritte semanticamente oppure i test senza valore
   sono rimossi; il disposition count finale è registrato in `docs/phpstan.md`.
6. Nessun `@phpstan-ignore`, baseline, exclude, nuovo `.neon`, inline `@var` correttivo,
   Service o Action proxy è introdotto. Immutabilità e connection `activity` restano
   invariati.

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

- Il comando canonico eredita `laravel/phpstan.neon`; sono vietati config derivati nel repo,
  baseline e soppressioni. [Source: `docs/bmad/context/sharding-context-phpstan-2026-08-24.md`]
- I test fanno parte del gate. Un test che cattura ogni eccezione o asserisce solo `true`
  deve essere messo in discussione, non semplicemente tipizzato. [Source:
  `docs/chat/phpstan-modules-regression-campaign.md`]
- Connection `activity` e log append-only sono invarianti di regressione. [Source:
  `01.08.connection-property-safety.story.md`; `ACTIVITY-7.1`]
- Prima di rimuovere un simbolo o sostituire una chiamata deprecata, verificare storia e API
  pubblica corrente. Non rendere pubblico un metodo per il solo test.

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- **Statico per file:** analizzare ogni file owned modificato con la configurazione root.
- **Statico module-wide:** cold `phpstan analyse Modules/Activity --no-progress`; validare
  `errors = 0`, `file_errors = 0` e stderr senza bootstrap/fatal.
- **Gate finale:** `phpstan analyse Modules` è certificato dalla meta-story XOT-5.23; la
  story registra comunque quanti findings globali sono attribuiti ad Activity.
- **Pest mirato:** fixture/ListLogActivities, QueryAndValidation, policy, Filament extended,
  remaining coverage, logout e provider. Nessun comando o test distruttivo.
- **Casi obbligatori:** gruppi DB/offline, config connection malformata, paginator tipizzato,
  actor/logout autentico, model mock Eloquent, Filament table corrente, fallimento reale
  dell'asserzione in caso di regressione.
- **Quality:** `php -l`, PHPMD e Insights se il toolchain è eseguibile; un fatal vendor è
  documentato come blocker del tool, non aggirato con modifiche fuori scope.

## Learnings from Previous Stories

- ACTIVITY-7.1 ha dimostrato che un gate module-wide non è chiudibile con owned scope
  parziale: questa story rende espliciti tutti i file residui.
- Le API interne del test runner e i getter Filament deprecati sono debito del test, non
  motivi per cambiare visibilità al codice applicativo.

## Dev Agent Record

### Implementation

- Fixture: generics espliciti per paginator/collection e return types aderenti al valore
  realmente restituito.
- TestCase: rimosso l'accoppiamento a `PHPUnit\Framework\TestCase::groups()` `@internal`;
  i marker DB/offline sono letti dal file Pest, le operazioni filesystem usano `Safe\` e
  la mappa connection è validata prima degli offset.
- Policy e recorder: harness tipizzati e aspettative Mockery reali; nessun inline `@var`
  contraddice il tipo nativo.
- Filament: rimossi tre test duplicati sui getter page deprecati; restano le verifiche
  delle classi Table/Schema correnti.
- Disposition: **7 test rimossi, 3 riscritti, 29 mantenuti**. Gli stati impossibili
  (`Logout` con user null e `MorphMany::getQuery()` non-Builder) non sono più fabbricati.
- Il test logout ora verifica la persistenza e ha documentato il contratto morph-map
  `causer_type = user`.

### Verification

- `php -l` sugli 11 file PHP owned: **PASS**.
- cold `phpstan analyse Modules/Activity`: **0 errors, 0 file errors** (baseline 39).
- Pest mirato finale: **29 passed, 65 assertions**.
- PHPMD: **BLOCKED** prima dell'analisi dal fatal vendor `PdependExtension::load()` vs
  firma Symfony `ExtensionInterface::load(...): void`.
- Insights: comando non installato.
- `graphify update .`: non avviato perché entrambi i graph root espongono un
  `.rebuild.lock` concorrente; nessun lock altrui è stato rimosso.
- Il gate globale resta di proprietà XOT-5.23; Activity non introduce config, baseline,
  ignore, Service o Action proxy.
