# Story: Activity Module Connection Property Safety

## Status: Draft

## Story

As a developer, I want to ensure that database connection properties in Eloquent models are never accidentally removed or modified, so that multi-database applications continue to function correctly.

## Context Source

- Source: User report of serious error regarding removal of `$connection = 'activity'` from Activity models
- Priority: Critical — connection properties are fundamental to multi-database architecture

## Why This Story Matters

In a multi-database Laravel application where each module uses its own database connection (e.g., `activity`, `ptv`, `indennita_responsabilita`), the `$connection` property in models is critical. Removing or modifying this property causes:

1. **Database connection errors** — models attempt to use the wrong database
2. **Data integrity issues** — queries execute against wrong tables/schema
3. **Application crashes** — Filament resources and other components fail to load
4. **Cascade failures** — one broken model affects all dependent components

**Note:** The reported error appears to be a false alarm or was already corrected. However, the story remains valuable for establishing safeguards.

## Root Cause Analysis

**Potential causes for accidental connection property removal:**
1. **Refactoring without understanding** — mass edits or automated refactoring tools
2. **Copy-paste errors** — creating new models from templates without connection awareness
3. **IDE auto-complete** — suggestions that override critical properties
4. **Merge conflicts** — incorrect resolution leading to property loss
5. **Code generation** — scaffolding tools that don't respect multi-database patterns

## Technical Requirements

### Prevention Mechanisms

1. **Base Model Enforcement**
   - Ensure all Activity models extend `BaseModel` which has the connection
   - Use abstract base classes to guarantee connection inheritance

2. **PHPStan/Static Analysis Rules**
   - Add custom rule to detect models missing `$connection` property
   - Validate connection property matches module naming convention

3. **Git Hooks**
   - Pre-commit hook to verify connection properties in modified model files
   - Block commits that remove critical connection properties

4. **Code Review Checklist**
   - Mandatory check for connection property in any model changes
   - Require explicit approval for connection property modifications

### Recovery Mechanisms

1. **Automated Tests**
   - Unit tests that verify model connections
   - Integration tests that query correct database for each model

2. **Database Validation**
   - Migration to verify each model's table exists in its designated connection
   - Health check endpoint to validate all module connections

## Notes

**Connection Property Pattern:**
```php
// Base class ensures connection inheritance
abstract class BaseModel extends XotBaseModel
{
    protected $connection = 'activity'; // ← CRITICAL: never remove
}

// Concrete models inherit connection automatically
class Activity extends BaseModel
{
    // No need to redeclare $connection unless different
}
```

**Warning Signs:**
- Database connection errors after model changes
- "Table not found" errors in wrong database
- Filament resources failing to load
- Models suddenly using default connection instead of module connection

**Emergency Recovery:**
If connection property is accidentally removed:
1. Check git history for the last known good state
2. Restore from git or manual inspection
3. Run tests to verify database connectivity
4. Check all related models in the same module
