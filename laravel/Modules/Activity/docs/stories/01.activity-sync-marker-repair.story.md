# Riparazione marker di sync nei test Pest di Activity

## Obiettivo

`phpstan analyse Modules` non parte se un PHP contiene `<<<<<<<` / `=======` / `>>>>>>>`. Lo script di sync
(`bashscripts/git/subtrees/merge_remote_repo_2.sh`) ne aveva committati dieci in `Modules/Activity/tests/Unit/`,
annidati fino a 8 livelli. Obiettivo: ogni test deve asserire il comportamento della classe di produzione
**attuale**, senza scegliere un lato alla cieca.

## Scope

Solo `laravel/Modules/Activity/tests/Unit/**/*.php` (10 file). Nessun file di `app/` modificato. Nessun
`RefreshDatabase`, nessun `migrate:fresh`.

## File, scopo, risoluzione

| File | Scopo del test | Risoluzione |
|------|----------------|-------------|
| `Actions/ActivityActionsUnitTest.php` | contratto costruttori di `ActivityMaintenanceAction` e `LogModel*`/`LogUser*Action` | merged: lato locale vuoto, corpo dal lato remoto |
| `Actions/Log/ListLogFilesActionTest.php` | elenco ricorsivo dei `.log`, ordinamento, limite, symlink fuori dir | merged: corpo completo |
| `Actions/Log/ResolveLogFilePathActionTest.php` | risoluzione sicura del path di un log (path traversal) | merged: 23 hunk annidati, verde |
| `Actions/QueryAndValidationTest.php` | validazione input di Query Actions, `ActivityLogger`, adapter | merged + corretto: `TestCase::mockeryExpect()` al posto della funzione globale; `with()` senza il quinto `null` che `ActivityRecorder::record()` non passa |
| `CanPaginateUnitTest.php` | trait `CanPaginate` senza database | merged: corpo completo |
| `Filament/ListLogActivitiesDeepCoverageTest.php` | rami di `ListLogActivities` | merged: corpo completo |
| `Filament/ListLogActivitiesRemainingCoverageTest.php` | rami residui di `ListLogActivities` e `ListLogActivitiesAction` | merged: corpo completo |
| `ListLogActivitiesPageCoverageTest.php` | breadcrumb, restore, paginazione della pagina | merged: 53 hunk, verde |
| `Listeners/LogoutListenerTest.php` | `LogoutListener` gestisce l'evento anche senza utente | merged, verde |
| `Models/SnapshotBusinessLogicTest.php` | connessione, `fillable`, parentela Spatie di `Snapshot` | merged + corretto: il caso sui `@method` ora asserisce le `@property` che `Snapshot` documenta davvero |

Righe scartate: nessuna riga con contenuto proprio. Sono stati rimossi solo i marker e i lati vuoti.

## Note di provenienza

Al momento della mia analisi un altro scrittore (non identificato, non lo script di sync, che girava nel
repository `base_ptvx_fila5`) stava gia' risolvendo gli stessi file; il commit `df495a3ef` li contiene
risolti. Ho verificato ogni file contro le classi di produzione e corretto solo i due test sopra.

## Verifica

- Marker in `Modules/Activity/**/*.php`: 0 (`git grep -E '^(<<<<<<<|>>>>>>>) '`).
- `php -l` verde sui file modificati.
- Pest (con `DB_DATABASE_USER=` vuoto): `QueryAndValidationTest`, `SnapshotBusinessLogicTest`,
  `ActivityActionsUnitTest`, `ListLogFilesActionTest`, `ResolveLogFilePathActionTest`, `CanPaginateUnitTest`,
  `LogoutListenerTest`, `ListLogActivitiesPageCoverageTest`: verdi (un caso `skipped` dichiarato in
  `LogoutListenerTest`).
- Rosso residuo, non causato dai marker: `ListLogActivitiesDeepCoverageTest` e
  `ListLogActivitiesRemainingCoverageTest` falliscono con `SQLSTATE[42S02] activity_log doesn't exist` nel DB
  `laravelpizza_data_test`. Il test di controllo `Actions/CoverageHundredActionsTest.php`, che non ha mai avuto
  marker, cade nello stesso modo. Serve applicare la migration `Activity` al DB di test.

## Anomalie non legate ai marker

`app/Models/Snapshot.php` contiene due docblock corrotti dal sync (`/** > */` sopra il `use HasXotFactory` e
`/** @laravel/Modules/UI/docs/bugfix-awstest-undefined-variable.md string */` sopra `$connection`). Non toccati:
fuori scope, da ripulire in una story dedicata del modulo.
