# 5.249: BMAD docs fleet: documenti canonici mancanti in ogni modulo

> **SUMMARY**: ogni modulo sotto `laravel/Modules/` deve avere i documenti BMAD
> canonici (README, architecture, brainstorming, epics, stories, quick-reference,
> setup-guide). I moduli "vuoti" vanno riempiti con contenuto **derivato dal
> codice reale**, non con testo generico.

## Perché

Il metodo BMAD è lo SSoT del processo di sviluppo di questo progetto
(`bashscripts/ai/wiki/memories/bmad-always-standing-order.md`,
`laravel/Modules/Xot/docs/bmad-method.md`). Un modulo con `architecture.md` e
`brainstorming.md` vuoti (stub TODO) non ha un processo: ogni agente che ci
lavora reinventa le convenzioni e le documenta altrove. Il drift è gia costato
fix ripetuti e marker di merge ricorrenti.

## Vincoli (impossibile ignorarli)

- Nessun file di codice PHP da toccare: scope = **solo** `docs/`.
- Nessun testo generico/AI-boilerplate: ogni affermazione deve essere verificata
  contro i file reali del modulo.
- `laravel/Modules/<Mod>/` e un repo git indipendente: `git status` va eseguito
  dentro il modulo.
- Ogni file scritto va lockato con `bash bashscripts/lock/lock.sh <path> <task> <agent>`.
- Nessun commit (forward-only, e l'utente non ha chiesto commit).
- NON creare/rimuovere/modificare `composer.json`, service provider o config: un
  `architecture.md` **non** e un posto dove proporre refactor non applicati.

### Debito emerso dagli stessi documenti (documentato, non risolto)

- **Activity**: 5 migrazioni creano la tabella `activity`; doppio
  `ActivityRecorderContract` (`app/Contracts/` e `app/Models/Contracts/`);
  `app/Enums/` vuota; `app/Http/*` solo `.gitkeep`; clone annidato
  `Activity/Activity/`.
- **Tenant**: nessuna migrazione crea la tabella `tenants`, pur avendo factory e seeder.
- **Job**: `config/config.php` e `config/Config/config.php` sono `[]` ma il codice
  legge `job::model` e `job::cache.*` (`ScheduleService` lo asserisce);
  `ExecuteTaskAction::execute()` lancia `BadMethodCallException`; Action duplicate
  tra `app/Actions/` e `app/Actions/Schedule/`; `tests/Unit/` e `tests/unit/`
  duplicati per casing.
- **Rating**: `routes/web.php` e `routes/api.php` senza rotte; 8 migrazioni attive
  sulla stessa tabella; `app/Filament/Resources/HasRatingResource/` senza classe
  Resource; ~90 file con marker di merge residui sotto `docs/bmad/`.
- **Performance**: 9 basename di Action duplicati; **Ptv/Performance**: 12 basename
  identici tra `Actions/Scheda` e `Actions/Organizzativa`; `ReportResource/` e
  `AnagResource/` senza classe Resource root in Ptv; doppio `CriteriPrecedenza`
  (Ptv default vs Progressioni in `boot()`).

## Cosa NON fare

- Non scrivere `architecture.md` come "questo modulo segue i pattern Laraxot":
  deve elencare i file reali del modulo.
- Non proporre refactor in un documento di architettura senza marcarlo esplicitamente
  come proposta non applicata.
- Non toccare `Activity/Activity/` (clone annidato committato): fuori scope.
