# 5.258: Prompt: prima eseguirli, poi migliorarli

> **SUMMARY**: 78 prompt in `bashscripts/docs/prompts/` (1,2 MB). Molti sono corrotti da
> concatenazioni (`02-` e `04b-` 4.400 righe con dentro l'intero prompt gitmodules; 18 file
> che ripetono il proprio corpo; blocchi `--- MERGED FROM`), ci sono fratelli con lo stesso
> numero e doppioni con numeri diversi. Ogni prompt viene **eseguito davvero** (l'esecuzione
> e' la prova di cosa nel prompt e' sbagliato, vecchio o ambiguo), poi **riscritto** con quello
> che l'esecuzione ha dimostrato.

## Perche'

Un prompt non si migliora leggendolo: si migliora eseguendolo e annotando dove l'agente si e'
bloccato (comando inesistente, path sbagliato, regola contraddittoria, gate non eseguibile).
Senza esecuzione un "miglioramento" e' solo riformattazione.

## Contratto per ogni subagent

1. **Esegui** ogni prompt del gruppo (in ordine random) come farebbe un agente che lo riceve:
   comandi reali, audit reali. Fix solo nei moduli assegnati, con lock
   (`bashscripts/lock/lock.sh <path> 5.258 <agente>` / `unlock.sh`) e ricontrollo mtime prima
   di ogni edit (story 5.257: il worktree e' scritto da altri agenti).
2. **Registra** per ogni prompt: cosa ha funzionato, cosa no, con l'evidenza (comando + output).
3. **Migliora**: un file canonico per argomento, riscritto su evidenza. Il contenuto unico perso
   dalla dedup concorrente va recuperato da `360bf54e` e ricollocato nel prompt giusto
   (anche di un altro gruppo: lo segnala nel report, non lo scrive).
   Fratelli/doppioni: **non** cancellarli e non rinominare: il consolidamento dei file e dei
   riferimenti lo fa il coordinatore alla fine (una sola passata, niente rotture incrociate).
4. **Closure gate** sui moduli toccati: `phpstan analyse Modules/<Mod>` (config sacra),
   phpmd, phpinsights, Pest (o skip documentato con la causa reale), `docs/coverage.md`,
   commit nel repo del modulo, pull+push su tutti i remote.
5. **Report** in `5.258-reports/<gruppo>.md` (un file per gruppo: nessun conflitto tra agenti).
