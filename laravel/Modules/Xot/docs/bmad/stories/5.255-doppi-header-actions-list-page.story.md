# 5.255: Ogni List page mostra due pulsanti «Crea»

> **SUMMARY**: Difetto **preesistente** trovato durante la story 5.254 e **non risolto**:
> `getHeaderActions()` (page header) e `getTableHeaderActions()` (table header) sono due
> barre distinte, entrambe renderizzate, ed entrambe mettono un `CreateAction`. Serve una
> **decisione di design** su quale dei due header sopravvive, non una rimozione silenziosa.

## Evidenze

| Dove | Cosa | Effetto |
|---|---|---|
| `XotBaseListRecords::getHeaderActions()` (`Modules/Xot/app/Filament/Resources/Pages/XotBaseListRecords.php:70`) | `['create' => CreateAction::make()->icon('heroicon-o-plus')]` | pulsante **Crea** nel page header |
| `HasXotTable::getTableHeaderActions()` (`Modules/Xot/app/Filament/Traits/HasXotTable.php:101`) | `$actions = [CreateAction::make()]` | pulsante **Crea** nel table header |
| `HasXotTable::table()` riga 253 | `->headerActions($this->getTableHeaderActions())` | il table header viene applicato |
| `vendor/filament/tables/resources/views/index.blade.php:315-319` | render del table header | il table header si vede |
| `InteractsWithHeaderActions::cacheInteractsWithHeaderActions()` | `$actions = $this->getHeaderActions()` | il page header si vede |

**Due "Crea" nella stessa schermata, in ogni List page di tutti i moduli.**

Su `CriteriEsclusioneResource` e `CriteriOptionResource` è **peggio**: `CopyFromLastYearAction`
appare **due volte**, perché sia le `BaseList*` (page header) sia le `*Table` (table header) lo
dichiarano. Verificato in `BaseListCriteriEsclusiones.php`, `BaseListCriteriOptions.php`,
`BaseCriteriEsclusionesTable.php`, `CriteriOptionsTable.php`.

## Perché non l'ho risolto in 5.254

La scelta riguarda **tutte** le List page di tutti i moduli, non le 6 di Ptv. Le due
ipotesi hanno costi diversi:

- **Togliere `getHeaderActions()` dal page header**: layout più pulito, ma il page header
  diventerebbe vuoto in molte schermate e si perde il modo naturale di aggiungere azioni
  **non** legate alla tabella.
- **Togliere il `CreateAction` da `HasXotTable::getTableHeaderActions()`**: si tengono
  `AssociateAction`, `AttachAction` e `TableLayoutToggleTableAction` (righe 104-107 del trait),
  che sono azioni **di contesto della tabella** e non hanno alternative nella barra della
  pagina. Candidato naturale, ma cambia il layout di ogni schermata.

Serve discussione con l'utenza e con gli altri agenti, non una scelta silenziosa.

## Domanda di accessibilità (oltre all'estetica)

Due controlli con la **stessa etichetta e la stessa azione** nella stessa vista è un problema
di accessibilità, non solo di layout: chi naviga da tastiera o da screen reader incontra
«Crea» due volte e non ha modo di sapere quale sia quello canonico. Se si sceglie un solo
header, la decisione va motivata anche da questo.

## Acceptance criteria

- [ ] Scelta documentata di quale header sopravvive (page header **o** table header), con il
      perché.
- [ ] Esattamente **un** `CreateAction` per schermata, verificato su almeno una List page per
      modulo.
- [ ] Nessuna azione di contesto della tabella persa (`AssociateAction`, `AttachAction`,
      `TableLayoutToggleTableAction`).
- [ ] `BaseListCriteriEsclusiones` / `BaseListCriteriOptions`: `CopyFromLastYearAction`
      presente **una** volta sola.
- [ ] PHPStan `level: max` senza baseline: 0 errori.
- [ ] Pest verde sui test Xot `no-db` (richiede `.env`, oggi assente).
- [ ] Nessuna `Table` class perde una colonna o un filtro per un effetto collaterale.
