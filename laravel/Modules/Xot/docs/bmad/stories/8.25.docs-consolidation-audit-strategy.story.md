# Story 8.25: Docs Consolidation Audit + Strategy

## Contesto

Audit delle cartelle `docs/` in 3 moduli chiave (Xot, Rating, IndennitaCondizioniLavoro) per identificare **duplicazioni, archivi obsoleti, strutture inconsistenti, e mancanze**. Produzione di una strategia consolidation replicabile per tutti i 19 moduli.

## Audit Findings

### Xot: HIGH CLUTTER (70+ directory)

**Problemi**:
- Duplicazioni: `-integration/` e `_integration/` (entrambi presenti)
- Archivi: `historical/`, `old_tasks/`, `raw/` (molto contenuto, poco utilizzato)
- Struttura duale: `docs/` root + `docs/wiki/` (confusione di livelli)
- Naming inconsistency: UPPERCASE + lowercase mixed

**Dettagli**:
- 70+ directory totali
- `docs/raw/` contiene 9 sottocartelle con "raw articles/notes/concepts"
- `docs/historical/`, `docs/old_tasks/` chiaramente archivi
- `docs/bmad/` ben strutturato, ma separato da `docs/wiki/`

**Impatto**: Difficile navigare, documentazione sparsa, discovery pessima.

### Rating: MEDIUM (duplicazioni minori)

**Problemi**:
- Duplicazioni: `00-INDEX.md` e `00-index.md` (due versioni di stesso file?)
- Naming: `INDEX_GENERATED.md` (sembra auto-generato, stale?)
- Uppercase/lowercase mixed: `BEST_PRACTICES.md` vs `best-practices.md` (quale è canonical?)

**Struttura OK**:
- `docs/` root con ~20 file
- `docs/stories/` dedicato e ben organizzato

**Impatto**: Ricerca confusa (quale INDEX è source of truth?), naming inconsistency.

### IndennitaCondizioniLavoro: MEDIUM (struttura incomplete)

**Problemi**:
- Manca `docs/wiki/` (tutta la doc è sotto `docs/bmad/`)
- Manca `docs/purpose.md` (ogni modulo dovrebbe avere scope esplicito)
- BMAD docs ricchi (architecture, patterns, audits) ma no separation tra:
  - **work tracking** (stories)
  - **long-term docs** (wiki)
  - **purpose/vision** (purpose.md)

**Struttura attuali**:
- `docs/bmad/` con architettura, migration audits, schema, performance notes
- `docs/stories/` con 4 story
- Niente `wiki/`, niente `purpose.md`

**Impatto**: Lavoro e documentazione mischiati, difficile capire "cosa fa questo modulo".

## Consolidation Strategy

### Target Structure (per modulo)

```
docs/
├── INDEX.md                     # Entry point, navigation
├── purpose.md                   # Explicit: "cosa fa questo modulo"
├── CHANGELOG.md                 # History, major changes
├── README.md                    # Quick intro (optional)
│
├── bmad/                        # Work tracking (BMAD method)
│   ├── stories/                 # Numbered stories (.story.md)
│   ├── architecture/            # Architecture decisions
│   ├── brainstorming/           # Open questions, proposals
│   ├── epics/                   # Epic definitions
│   └── workflows/               # Process docs
│
├── wiki/                        # Long-term, stable docs
│   ├── architecture/            # System design, patterns
│   ├── concepts/                # Key concepts, glossary
│   ├── how-to/                  # Recipes, guides
│   ├── reference/               # API docs, schemas
│   ├── decisions/               # ADRs (Architecture Decision Records)
│   └── archive/                 # Timestamped old docs (2026-09/, 2026-08/, ...)
│
├── schema/                      # (optional) Database schema
├── screenshots/                 # (optional) Visual references
└── assets/                      # (optional) Images, diagrams
```

### Consolidation Checklist

**Phase 1: Naming & Deduplication**
- [ ] Scan duplicate files (sha1, size)
- [ ] Rename to lowercase filenames, Capital headers
- [ ] Keep single INDEX.md (delete 00-index.md, 00-INDEX.md variants)

**Phase 2: Archive Old**
- [ ] Move `historical/`, `old_tasks/`, `raw/` → `wiki/archive/{timestamp}/`
- [ ] Merge `-integration/` + `_integration/` → single `_integration/`

**Phase 3: Add Missing**
- [ ] Create `purpose.md` (every module, even if placeholder)
- [ ] Create `INDEX.md` if missing
- [ ] Create `CHANGELOG.md` if missing

**Phase 4: Reorganize**
- [ ] Ensure `wiki/` structure exists (architecture/, concepts/, how-to/, reference/, decisions/)
- [ ] Move long-term docs to `wiki/`
- [ ] Move work tracking to `bmad/`

**Phase 5: Link Maps**
- [ ] Update module `INDEX.md` with links to all sections
- [ ] Update root `MEMORY.md` with docs locations

## Implementation Plan

### Swarm Approach (6 cluster paralleli)
Reuse the PHPStan cluster strategy:
- **Cluster 1**: IndennitaResponsabilita, Progressioni, Sigma (consolidate)
- **Cluster 2**: Lang, Pdnd, UI
- **Cluster 3**: Notify, ICL, User
- **Cluster 4**: Rating, Media, Incentivi
- **Cluster 5**: Xot, Performance, Ptv
- **Cluster 6**: Job, Activity, Tenant

Ogni cluster: apply consolidation checklist → 1 BMAD story per cluster.

## Success Criteria

- [ ] 0 duplicate files (deduplicated & merged)
- [ ] 100% modules have `docs/purpose.md`
- [ ] 100% modules have `docs/INDEX.md`
- [ ] All `wiki/` subdirectories structured consistently
- [ ] `archive/` contains timestamped old content
- [ ] Root `MEMORY.md` maps all docs locations
