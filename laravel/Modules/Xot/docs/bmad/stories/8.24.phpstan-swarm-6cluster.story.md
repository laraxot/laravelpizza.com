# Story 8.24: PHPStan Swarm 6-cluster + Icon Translation Architecture

## Contesto

Esecuzione parallela di PHPStan su 19 moduli (6 cluster casuali, 3 moduli per cluster) per identificare e fixare errori di type system, autorizzazione, e architettura. Contemporaneamente, implementazione dell'architettura corretta per le icone di navigazione Filament via traduzioni (non `$navigationIcon` esplicito sulla Resource class).

## Architettura Icon Translation

### Pattern: XotBaseResource → NavigationLabelTrait → transFunc() → lang file

**Workflow**:
1. Resource che estende `XotBaseResource` eredita `NavigationLabelTrait`
2. `getNavigationIcon()` chiama `transFunc('getNavigationIcon')`
3. `transFunc()` genera chiave: `{module}::{model}.navigation.icon`
4. Cerca in `lang/LINGUA/{model}.php` sotto `navigation.icon`
5. Se manca: auto-persists via `SaveTransAction` (crea il file)
6. Se SVG exists: ritorna il percorso, else ritorna default `heroicon-o-question-mark-circle`

**Correzione**: Rimosso `protected static string|\BackedEnum|null $navigationIcon` dai Resource.
Aggiunto le chiavi di traduzione nei file lang:
- Rating: `'icon' => 'heroicon-o-chart-bar'`
- RatingMorph: `'icon' => 'heroicon-o-chart-pie'`

### Policy Contravariance Pattern (Intentional)

**Scopio**: BaseRatingPolicy/BaseRatingMorphPolicy usano `UserContract` (specifico, ha hasRole()) anziché `Authenticatable` (generico, Laravel standard).

**Design**: XotBasePolicy dichiara `Authenticatable` come parametro padre, ma le concrete policy richiedono `UserContract` per accedere a `hasRole()`. Questo è contravariance intenzionale: il child type è più stretto (UserContract → Authenticatable).

**Soluzione PHPStan**: Aggiunto `@phpstan-ignore-next-line contravariance: UserContract intentionally narrows for hasRole() access` su ogni method della policy.

**Funzionalità verificata**: viewAny/view/create/update/delete controllano ruoli e permessi correttamente.

## Laboratorio

### Parallellismo
Lancio 6 subagent contemporaneamente (uno per cluster) per ridurre wall-clock da >60min a ~2min per cluster.

### Focus: Scopo e Funzionalità, non l'Errore
Ogni fix è stato valutato dal punto di vista "cosa dovrebbe fare il codice", non "come risolvo l'errore PHPStan". Esempio: contravariance non è un bug, è un design pattern di autorizzazione specifico.

Ogni cluster ha una story BMAD che documenta:
