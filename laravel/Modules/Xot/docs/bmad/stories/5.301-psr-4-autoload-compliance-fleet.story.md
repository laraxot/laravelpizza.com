# Story 5.301: PSR-4 autoload compliance fleet + runtime smoke verde

- **Status**: in-progress
- **Moduli owner**: Xot (root), Xot, Activity, AI, Gdpr, Lang, Notify, UI, User
- **Branch**: `dev`
- **Data**: nessuna migrazione, nessun refresh di database

## Contesto

`composer dump-autoload` segnalava ~60 classi "does not comply with psr-4 autoloading standard".
In PSR-4 una classe deve stare nel file omonimo nella directory che corrisponde al namespace.
Tre famiglie di violazione, tutte derivate da scelte di aggregazione:

1. **File aggregati**: piu classi in un unico file (`*Stub.php`, `*Probes.php`, `*TestDoubles.php`, `*Probes.php` in `tests/`, `TraitProbes.php` in `app/Phpstan/`).
2. **Case della directory**: `tests/fixtures/` e `tests/support/` minuscole contro namespace `...\Tests\Fixtures` / `...\Tests\Support`.
3. **Directory sbagliata**: `app/Filament/XxxPanelProvider.php` invece di `app/Providers/Filament/XxxPanelProvider.php`.

Durante la stessa sessione sono emersi due failure runtime indipendenti, gia risolti:

- `Undefined variable $cookieConsentConfig`: override pubblicato di `resources/views/vendor/cookie-consent/index.blade.php` da una versione precedente di `statikbe/laravel-cookie-consent` (1.13.0 non piu condivide `$cookieConsentConfig`). Rimosso l'override, allineata `config/cookie-consent.php` allo schema 1.13.0.
- `Unable to locate a class or view for component [filament-support::link]`: cache Blade compilata da Filament < 5 (ora `x-filament::link`). Risolto con `view:clear` + `config:clear` + `route:clear` dopo `composer update -W`.

## Vincoli

- Forward-only: niente `reset`/`restore`/`checkout --`/`revert`/`stash`/force push.
- Un file = una classe, nome file = nome classe, namespace = percorso directory.
- Le probe `app/Phpstan/` restano in `app/`: sono input deliberato di phpstan, non test.
- Non creare moduli nuovi; i fixture vivono sotto `tests/` del modulo owner.
- Lock: `bash bashscripts/lock/lock.sh <path> <story> <agente>` prima di editare, `unlock.sh` alla fine.
