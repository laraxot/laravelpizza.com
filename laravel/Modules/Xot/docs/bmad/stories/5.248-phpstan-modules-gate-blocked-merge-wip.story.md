# 5.248: PHPStan `analyse Modules` non eseguibile

## Perchè

Richiesta: `cd laravel && ./vendor/bin/phpstan analyse Modules` e sistemare tutte le segnalazioni.
Il comando **non arriva all'analisi**: il bootstrap dell'applicazione fallisce e l'errore cambia a ogni
esecuzione, perché il tree è in scrittura continua da parte di altri agenti.

## Evidenze (2026-09-28, cwd `laravel/`)

- `phpstan analyse Modules` → `Application bootstrap failed`, `Error: syntax error, unexpected token "<<", expecting end of file` (run successive: `unexpected token "<<", expecting "function"`, `Unclosed '{' on line 60 does not match ')'`).
- `vendor/bin/parallel-lint Modules` (esclusi `vendor`/`.git`/`node_modules`) → **349 file con parse error**: Notify 201, Activity 68, Job 43, Lang 30, Media 7.
- Provider di servizio rotti (caricati dal bootstrap, quindi bloccano tutto): `Modules/Notify/app/Providers/NotifyServiceProvider.php`, `Modules/Notify/app/Providers/Filament/AdminPanelProvider.php`, `Modules/Lang/app/Providers/LangServiceProvider.php` (quest'ultimo riparato nel frattempo: i marker spariscono e ricompaiono).
- Marker di merge: 216 file `.php` sotto `Modules` in un momento, 0 due minuti dopo, poi di nuovo: **il contenuto fluttua mentre si lavora**.
- `find Modules -name '*.php' -newermt '-3 minutes' -not -path '*/vendor/*'` → **592 file modificati in 3 minuti**: scrittura concorrente attiva.
- `git ls-files -u` = 0 e `git status` mostra solo ` M`: i marker sono **committati**, git non li segnala come unmerged.
- Lock di altri agenti sulla stessa campagna: `bashscripts/lock/git-conflicts-L3-{Activity,Lang,Rating,UI,Xot}-docs.lock`, `phpstan-{IndennitaResponsabilita,Rating,UI}.lock` (età ~3,8 giorni, stale per età ma lavoro ancora in corso).

## Root cause

**Correzione del 2026-09-28 sera.** La diagnosi iniziale (sopra, "marker
committati in HEAD") era **sbagliata**. Prove raccolte:

- `git rev-parse HEAD` == `git rev-parse laraxot/dev` == `1616dde94`; nessuna
  merge in corso (`git ls-files -u` = 0, `.git/MERGE_HEAD` assente, nessun rebase).
- `git grep -l '^<<<<<<<' HEAD -- 'laravel/Modules/*.php'` = **0** → HEAD e pulito.
- I marker erano **spazzatura iniettata nel worktree** da un merge abortito, della
  stessa eta dei lock stale `git-conflicts-L3-*.lock` del 24/09 20:56.
- 15084 file sporchi in totale, di cui 739 `.php` con marker.
- Cause dell'interferenza continua: un altro agente stava eseguendo
  `git lfs migrate export --everything --include=*.png,*.svg,... -y` +
  `git-lfs-transfer ... laraxot/module_job_fila5.git Download`, che riscriveva
  il worktree in massa. Il conteggio marker oscillava 175 -> 303 -> 89 -> 7 ->
  709 -> 507.

Dopo la riparazione i marker sono **ricomparsi due volte** (Activity 19:35,
ancora Activity 19:48): la concorrenza e reale, non un errore di diagnosi.

## Come e' stato risolto (2026-09-28, 19:20–19:50)

1. **739 file `.php` con marker** ripristinati da HEAD via
   `git show HEAD:<path> > path` (mai `git checkout --`, mai index, mai history).
   Backup: `/tmp/kilo/marker-backup-20260928-192503.tar.gz`.
2. Restavano **136 parse error di altra natura**: dichiarazioni duplicate da merge
   "risolto" male (marcatori rimossi, due lati concatenati): es. doppio
   `class Repeater`, doppio `return new class`, metodo troncato piu gemello.
   Verificato su HEAD: 135 risolvibili ripristinando, **1 rotto anche in HEAD**
   (`Modules/Lang/docs/italian-text-validation-refined.php`, `docs/` e gia
   escluso da `phpstan.neon`).
3. **135 file ripristinati da HEAD**. Backup:
   `/tmp/kilo/parse-backup-20260928-192646.tar.gz`.
4. Attesa che l'attivita di scrittura esterna si fermasse (misura dei file `.php`
   modificati ogni 30s: 734, 6, 40, 0, 0, 0, 0, 0 alle 19:38).

## Cosa NON fare

- Non "fixare" i 349 file: sono il WIP di altri agenti (lock attivi), i fix verrebbero sovrascritti e
  aggraverebbero i conflitti. Violerebbe la lock discipline e la regola "correggi solo i tuoi file".
- Non creare baseline, non toccare `phpstan.neon` (neon sacro), niente `--level`/`-c`.
- Non rimuovere i `.lock` freschi a mano; per età ≥10 min prima sbloccare con `unlock.sh` e annunciare
  lo scope nella story.

## Piano quando il tree è stabile

1. Preflight del prompt 03 v3.34.0: il check marker (scope + file critici) deve uscire pulito.
2. `php artisan --version` verde → bootstrap OK.
3. `parallel-lint Modules` = 0 parse error.
4. Solo allora `phpstan analyse Modules --no-progress --memory-limit=-1` e campagna di fix **per modulo**,
   con lock per file e story dedicata.
5. Aggiornare `laravel/Modules/Xot/docs/phpstan-status.md` con la misura reale.

## Second brain

Memoria consolidata in
[`laravel/Modules/Xot/docs/wiki/memories/merge-marker-spazzatura-worktree.md`](../../wiki/memories/merge-marker-spazzatura-worktree.md):
*"un parse error in un service provider blocca l'intero gate PHPStan/Pest/artisan,
indipendentemente dallo scope analizzato. I marker `<<<<<<<` possono essere
**spazzatura nel worktree** e non in HEAD: `git grep` su `HEAD` e l'unico
rilevamento affidabile, `git status` non li mostra. Prima di ripristinare,
verificare che `git show HEAD:<path>` sia sintatticamente valido e che l'hunk
sia davvero rumore: per `lang/**.php` la fusione corretta e l'unione delle
chiavi, non il restore."*

Regola operativa derivata: **misurare i file `.php` modificati negli ultimi 3
minuti** prima di editare, e non fidarsi del solo `git status`.
