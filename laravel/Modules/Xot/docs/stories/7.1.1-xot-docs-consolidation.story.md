## Benefits

1. **Discoverability:** Files are now categorized by intent (purposes, testing, integration, backlog)
2. **Maintainability:** Clear separation between canonical docs (wiki) and work-in-progress (stories)
3. **BMAD Compliance:** Xot now follows the same structure as exemplary modules (Rating, Sigma, Ptv, IndennitaResponsabilita)
4. **Legacy Clarity:** Superseded docs are marked as legacy, not deleted (important for historical context)

## Why Not...

- **Delete legacy files?** No: they're part of the project's decision trail. Marking as `legacy-` is cheaper than losing context.
- **Add more categories?** No: kept to minimum (purposes, testing, integration). New categories can be added on-demand when needed.

## Notes

The `purpose.md` file is strategically important: it documents why Xot exists (foundation module, not domain), the case for inheritance over composition, and 5 actions to improve module governance. This document should be linked in the Xot README or decision-log.

Similar strategic docs in other modules (Rating, Ptv) are in docs/wiki/ subdirectories. Xot's structure now follows this pattern.
