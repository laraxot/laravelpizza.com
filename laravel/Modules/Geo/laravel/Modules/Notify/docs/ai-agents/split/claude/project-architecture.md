## FIXCITY PROJECT ARCHITECTURE

### Core Understanding
This is **FixCity**, a **citizen reporting platform** for urban issue management. Citizens report problems, administrators manage them.

### System Architecture - NWIDART + LARAXOT ECOSYSTEM
- **Modular Monolith** using Nwidart/Laravel-Modules + Laraxot extensions
- **Backend**: Laravel 12.24.0 + PHP 8.3.20 + SQLite
- **Backoffice**: Filament 3.x + Laraxot (admin panels)
- **Frontoffice**: Folio + Volt + Livewire 3.x (citizen interface)
- **Module System**: Nwidart base + Laraxot enhancements
- **NO Traditional Routes**: Routes are EMPTY - uses Folio file-based routing + Filament panels
- **NEVER use web.php or api.php for routing** - files exist but are empty

### Nwidart + Laraxot Integration
```
Modules/
├── module.json          → Nwidart module definition
├── composer.json        → Module dependencies (merge-plugin)
├── app/
│   ├── Models/         → Extend XotBaseModel
│   ├── Providers/      → Extend XotBaseServiceProvider
│   └── Filament/       → Filament Resources/Widgets
├── resources/views/pages/ → Folio pages (when needed)
├── routes/            → Empty files (not used)
└── docs/              → Documentation (DRY + KISS)
```

### Module Status Management
- `modules_statuses.json` - Controls which modules are active
- All 22 modules currently active (Activity, Geo, Blog, Cms, Gdpr, Job, Media, Notify, Rating, Tenant, UI, User, Xot, Lang, Chart, Fixcity, Ticket, AI, Comment, Seo)
- Automatic discovery via composer merge-plugin

### Theme System
```
Themes/Sixteen/
├── resources/
│   ├── css/app.css      → Theme styles (Tailwind)
│   ├── js/             → Theme JavaScript
│   ├── views/pages/    → Folio pages
│   └── dist/           → Compiled assets (target)
├── tailwind.config.js   → Theme-specific Tailwind config
├── package.json        → Theme dependencies
└── vite.config.js      → Theme build config
```

### Critical Modules
- **Xot**: Framework base (XotBaseModel, XotBaseServiceProvider, core patterns)
- **Fixcity**: Core ticket system (main business logic)
- **User**: Authentication, profiles, permissions
- **Cms**: Content management, pages (JSON storage)
- **Geo**: Geographic data (addresses, coordinates)
- **Notify**: Multi-channel notifications
- **UI**: Shared interface components
- **Lang**: Multi-language support

### Key Models & Relations
```php
Ticket (core entity):
- extends: XotBaseModel (Laraxot pattern)
- belongsTo: owner, responsible (User)
- hasMany: activities, hours, comments, relations
- supports: geolocation, media attachments, status tracking
- uses: Enums for status/priority/type
```

### Routing Patterns - NO TRADITIONAL ROUTES
```php
// ROOT routes are EMPTY
/laravel/routes/web.php    → EMPTY (only declare statement)
/laravel/routes/api.php    → DOES NOT EXIST

// MODULE routes are EMPTY  
/Modules/*/routes/web.php  → EMPTY
/Modules/*/routes/api.php  → EMPTY (some have minimal API)

// ACTUAL ROUTING:
// 1. Folio Frontend (citizen-facing)
/it/tickets/create → Themes/Sixteen/resources/views/pages/tickets/create.blade.php
/it/tickets/{slug} → Modules/Fixcity/resources/views/pages/tickets/[slug].blade.php

// 2. Filament Admin Panels (staff-facing)
/fixcity/admin/tickets → Auto-generated by TicketResource
/user/admin/users → Auto-generated by UserResource
```

### Documentation Strategy (DRY + KISS)
- **docs/ folders** = Project memory and knowledge base
- **Continuous documentation** = Update docs with every change
- **Bidirectional links** = Connect related documentation
- **DRY principle** = Don't repeat information
- **KISS principle** = Keep documentation simple and accessible

### Development Workflow
1. **Frontend changes**: Always work in `Themes/Sixteen/`
2. **CSS/JS changes**: Always run `npm run build && npm run copy`
3. **New pages**: Use `php artisan folio:page` (in Theme or Module)
4. **Admin features**: Create Filament Resources
5. **Interactivity**: Use Livewire Volt components (@volt directive)
6. **Models**: Extend XotBaseModel (never direct Eloquent Model)
7. **Testing**: Use Pest for all tests
8. **Documentation**: Update docs/ with every change

### Laraxot Patterns
- **Base Classes**: Always extend Xot* base classes
- **Service Providers**: Extend XotBaseServiceProvider
- **Route Providers**: Extend XotBaseRouteServiceProvider (but routes stay empty)
- **Models**: Extend XotBaseModel
- **Updater Trait**: Automatic created_by/updated_by tracking

### Business Logic
FixCity enables:
- Citizens to report urban issues (potholes, broken lights, etc.)
- Automatic geolocation and photo attachments
- Administrative workflow with assignments and status tracking
- Multi-channel notifications and updates
- Complete audit trail and reporting

This is a mature, production-ready civic engagement platform built on Nwidart + Laraxot architecture.
