# Story 7.2-LANG: Contratti PHPStan test harness

## Story

Come maintainer Lang, voglio correggere i contratti statici dei test harness e dei
test coverage, affinché il gate module-wide raggiunga zero senza soppressioni né
asserzioni prive di significato.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. PHPStan su `Modules/Lang` termina con zero errori usando la configurazione root
   invariata e includendo tutti i test.
2. Le funzioni filesystem/processo fallibili usano le varianti Safe o un controllo
   esplicito del risultato, preservando cleanup e isolamento delle fixture.
3. Config, traduzioni, payload JSON e collection vengono ristretti tramite contratti
   verificabili prima di offset, iterazione o accesso a proprietà.
4. Mock e fixture dichiarano il tipo concreto/intersection necessario; gli helper
   condivisi sono invocabili dal contesto Pest reale e hanno generici completi.
5. Le API deprecate vengono sostituite con l'equivalente corrente e le asserzioni
   tautologiche diventano verifiche semantiche del comportamento osservabile.
6. Nessun ignore, baseline, exclude, config locale, cast cosmetico, stub locale,
   Service nuovo o `mixed` evitabile è introdotto.

### Root causes

- **Filesystem/process boundary:** `getmypid`, `touch`, `mkdir`, `rename`, `rmdir`,
  `fopen`, `fclose` e `unlink` possono fallire; usare `Safe\*` quando l'eccezione è
  il contratto desiderato, oppure testare il booleano quando il fallimento è parte
  del caso. Non rendere il cleanup distruttivo. [Source:
  bmad-output/architecture.md#adr-003-pest-via-xotbasepest-classe--xotbasetestcase]
- **Pest helper context:** chiamate `self::createTranslationFile()` vivono fuori da
  uno scope di classe. Spostare il comportamento in closure/helper di dominio già
  caricato o invocarlo sul TestCase concreto; non creare `tests/Support` o bridge.
  [Source: bmad-output/architecture.md#adr-002-vietato-testssupport-per-modulo]
- **Opaque framework values:** `config()`, traduzioni, JSON e facade restituiscono
  valori larghi. Validare shape e chiavi una volta al boundary, poi fare asserzioni
  sui valori reali. `mixed` resta ammesso solo nel punto realmente opaco e va
  ristretto subito. [Source: bmad-output/architecture.md#adr-011-mixed--ultima-spiaggia]
- **Mock/model contracts:** usare intersection types come `Model&MockInterface` o
  fixture concrete quando il test chiama API Eloquent; non dichiarare il solo
  `MockInterface` e poi accedere a proprietà/metodi del model.
- **Framework migrations:** sostituire `getTableColumns()` e
  `DataCollection::first()` deprecati attraverso le API pubbliche correnti, testando
  lo stesso risultato anziché dettagli interni.
- **Coverage-only tautologies:** `assertTrue(true)`, `assertIsArray()` su array già
  noto, `method_exists()` sempre vero e assert di non-null su ritorni non-null non
  dimostrano comportamento. Verificare contenuto, trasformazione o side effect.

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- PHPStan scoped su ciascuno dei sei file, poi
  `./vendor/bin/phpstan analyse Modules/Lang --no-progress` con configurazione root.
- Pest mirato ai cinque file unitari e al TestCase tramite i loro consumer; nessun
  `RefreshDatabase`, nessun dato persistente distrutto.
- Fixture filesystem: file mancante, non leggibile, vuoto, nested, rename/cleanup e
  directory già esistente; ogni path deve vivere nello spazio temporaneo del test.
- Boundary dati: config mancante o malformata, traduzione stringa/array, country
  assente, JSON non-array, collection vuota e payload con chiavi inattese.
- Filament/Data: verificare colonne/componenti e URL risultanti tramite API pubbliche,
  non metodi deprecati o proprietà interne.
- Mock: verificare chiamate/side effect sul modello concreto; vietate asserzioni
  tautologiche aggiunte solo per coverage.

## Learnings from Previous Stories

Un gate module-wide non è chiudibile da una story che possiede solo l'applicazione:
la story test-harness deve possedere esplicitamente ogni file residuo e mantenere
separati i boundary opachi dalle asserzioni di dominio.
