# JOB-4.31: `Schedule` class constants: real type declarations for `typeCoverage.constantTypeCoverage`

## Contesto

Campagna repo-wide "PHPStan Modules a zero errori". Il bucket dominante e'
`typeCoverage.constantTypeCoverage`: una percentuale calcolata su **tutto** l'albero
`Modules/` (non per singolo modulo: `phpstan analyse Modules/Job` da solo non la
mostra, serve `phpstan analyse Modules`), che richiede 99%+ di costanti di classe con
un **type declaration reale** (PHP 8.3+), non un `@var` PHPDoc.

File di questa story: `app/Models/Schedule.php`, costanti `STATUS_INACTIVE`,
`STATUS_ACTIVE`, `STATUS_TRASHED`.

## Attenzione: WIP di un'altra sessione scartato/corretto

All'apertura della story, `git status` mostrava `app/Models/Schedule.php` gia'
modificato (non committato) da una sessione precedente/concorrente: aveva aggiunto
`/** @var int */` sopra ciascuna costante, **senza** toccare la dichiarazione `const`
stessa. Questo e' esattamente il pattern sbagliato documentato in
`docs/chat/typecoverage-constant-wrong-var-list-string-regression.md`: un `@var`
PHPDoc non sposta la percentuale di `constantTypeCoverage`, solo un type declaration
reale sulla `const` lo fa. Il WIP e' stato sostituito con il fix corretto (vedi sotto),
nessun'altra modifica di quella sessione toccata.

## Fix applicato

```php
// prima
public const STATUS_INACTIVE = 0;
public const STATUS_ACTIVE = 1;
public const STATUS_TRASHED = 2;

// dopo
public const int STATUS_INACTIVE = 0;
public const int STATUS_ACTIVE = 1;
public const int STATUS_TRASHED = 2;
```

Nessun `@var` PHPDoc aggiunto: e' ridondante una volta che il type declaration reale
c'e', e nessun'altra costante scalare intera del modulo lo usa (vedi
`Rating/app/Filament/Blocks/Rating.php:23` come precedente corretto gia' verificato
per lo stesso bucket).

## Verifica usi

`grep -rn "Schedule::" Modules/Job` (app + tests): nessun uso esterno di
`Schedule::STATUS_*`. Uso interno solo in `scopeInactive()`/`scopeActive()` via
`self::STATUS_INACTIVE` / `self::STATUS_ACTIVE`: valore invariato, solo il tipo
dichiarato e' cambiato, rischio di rottura nullo.
