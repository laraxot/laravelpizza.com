# 4.28 PHPStan L10: pulizia residui `mixed` e tipi generici

## Contesto

Dopo le story 4.26 e 4.27, `phpstan analyse Modules --memory-limit=-1` riporta ancora 4
segnalazioni reali (più 1 soppressa da `phpstan.neon` ma riferita):

| # | File | Identificatore | Sintomo |
|---|------|----------------|---------|
| 1 | `Job/app/Actions/GetTaskCommandsAction.php:42` | `argument.type` | `sortBy` riceve `Closure(Command): non-falsy-string` ma firma accetta `callable(mixed, int|string)` |
| 2 | `User/app/Filament/Resources/TenantResource/RelationManagers/DomainsRelationManager.php:54` | `return.type` | ternario restituisce `''\|Stringable` invece di `string` |
| 3 | `User/app/Models/Traits/InteractsWithTenant.php:76` | `instanceof.alwaysTrue` + `notIdentical.alwaysTrue` | dopo `is_int($tenantId)`, controlli su `Model` sempre veri |
| 4 | `User/tests/Unit/Models/Traits/MockUserWithTeams.php:19` | `generics.notGeneric` | `@use RelationX<Model>` ma `RelationX` non è generico |

## Vincoli

- No `phpstan-ignore-*`, no baseline, no `phpstan.neon` modificato.
- Regola `phpstan-fix` skill: `Webmozart\Assert\Assert` per narrowing, `casts()` method, niente `property_exists()`.
- Pattern `laraxot-pre-commit`: dopo ogni fix → `phpstan + phpmd + phpinsights + pest`.
- BMAD obbligatorio: questo file è la story; il dev la esegue in avanti (`git forward-only`).

## Acceptance criteria

- [ ] `cd laravel && ./vendor/bin/phpstan analyse Modules --memory-limit=-1` → 0 errori.
- [ ] `cd laravel && ./tools/phpmd.sh <file>` (per ciascun file toccato) → 0 errori.
- [ ] `cd laravel && ./tools/phpinsights.sh <file>` → no regression su code / complexity.
- [ ] `cd laravel && ./vendor/bin/pest Modules/Job Modules/User --compact` → verde.
- [ ] Coverage Pest invariata o in crescita (target minimo: nessun file toccato perde punti).

## Strategia di fix

### Fix 1: `GetTaskCommandsAction.php`

Sostituire `mixed $command` con `Command $command` (la collezione è già
`Collection<int, Command>` via `Artisan::all()`) e rimuovere `Assert::isInstanceOf`
interno. Il callable passa da `(mixed $c): string` a `(Command $c): string`,
allineato alla firma di `sortBy`.

### Fix 2: `DomainsRelationManager.php`

`Str::of(...)->toString()` già usato; aggiungere cast esplicito a `string` sul
risultato di `toString()` e dichiarare il return del closure come `: string`
(già presente). Il ternario deve essere `'' . $maybeStringable` oppure
`is_string(...) ? ... : ''` per non lasciare il ramo `Stringable`.

### Fix 3: `InteractsWithTenant.php`

Alla riga 76 il problema è che `$tenant` è già typed da `Filament::getTenant()`
come `Model|null`; il check `if ($tenant !== null)` non è la causa del
warning, bensì il check `is_int($tenantId)` interno. PHPStan segnala che
`$tenantId` (return di `getKey()` su Model) è sempre `Model` prima del check.
Soluzione: rimuovere il confronto `$tenant !== null` post-`loadTenantFromSession`
quando ridondante, oppure sostituire con `if ($tenant === null) { return; }`
semplificando il flusso.

### Fix 4: `MockUserWithTeams.php`

`RelationX` non è generico (controllato: `bashscripts/ai/wiki/rules/` non
richiede generics su RelationX). Rimuovere il docblock `@use` e tenere solo
`use RelationX;`.
