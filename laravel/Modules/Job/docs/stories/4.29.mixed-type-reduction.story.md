# JOB-4.29: Ridurre `mixed` dove il tipo e' realmente noto

## Contesto

Convenzione di progetto: "cerchiamo di non usare `mixed`, quando lo troviamo cerchiamo di
sostituirlo con qualcosa di adeguato": best-effort ("dove possibile"), non 100% coverage.
Vedi memoria `type-coverage-non-conta-mixed`: il plugin `tomasvotruba/type-coverage` non
conta `mixed` come tipo, quindi il lavoro e' analisi del dominio (da dove viene il valore?),
non annotazione meccanica.

Censimento: 65 occorrenze di `mixed` su 48 file in `Modules/Job` (`grep -rnE '\bmixed\b'
Modules/Job --include="*.php"`).

## Collisione trovata prima di iniziare

`git status --short` su `Modules/Job` mostrava **177 file gia' modificati e non committati**
da un'altra sessione (import reordering, `.gitattributes` ridotto, migrazione
`ScheduleService` → `Actions/Schedule`; coerente con `docs/chat/module-job-sync.md`, che
descrive lo stesso lavoro gia' committato una volta come `6cf329e`: quindi questo e' un
**secondo giro** di modifiche non ancora committate sopra quel commit). Per non
sovrascrivere/perdere lavoro altrui (regola `var-override-before-git-log-check` /
`multi-agent-same-repo-race`), gli edit di questa story sono stati **limitati ai file senza
diff pre-esistente**: 30 dei 48 file con `mixed` erano puliti, 18 erano gia' dirty.

`docs/coverage.md` era anch'esso gia' dirty: il working tree lo aveva **sostituito** con una
versione piu' vecchia/grezza (frontmatter e struttura pre-story-4.26) rispetto a quella
committata in HEAD (struttura post-4.26, con contratto di qualita'). Non e' stato causato da
questa sessione ne' corretto: l'aggiornamento richiesto da questa story e' stato aggiunto in
coda come sezione datata, senza toccare il resto del file: ma il commit di questa story
include comunque quel diff pre-esistente (non separabile senza un cherry-pick manuale di
hunk). Segnalato al coordinatore.

## Cosa e' stato cambiato

Un solo cambiamento sicuro, verificato: `app/Http/Livewire/Job/Status.php`, docblock di
`public array $form_data` da `array<string, mixed>` a `array<string, string>`: l'unico
campo mai assegnato o bindato (`conn`, connessione coda) e' sempre una stringa, sia in
`mount()` sia nel binding `wire:model.lazy="form_data.conn"` di
`resources/views/livewire/job/status.blade.php`.

## Cosa e' stato valutato e lasciato `mixed` (con motivo)

| File/i | Motivo |
|---|---|
| `database/factories/*Factory.php` (17 file) | `definition(): array` sovrascrive `Illuminate\Database\Eloquent\Factories\Factory::definition()`, il cui contratto vendor e' `@return array<string, mixed>` (verificato in vendor). Narrowing romperebbe la compatibilita' di firma. |
| `app/Models/{Job,FailedJob,JobsWaiting,FailedImportRow,ScheduleHistory}.php` | `@property array<array-key, mixed> $payload/$data/$params/$options`: colonne JSON genuinamente polimorfe (payload di job serializzati, dati di riga import falliti). |
| `app/Rules/Corn.php` | `validate(string $_attribute, mixed $value, Closure $fail): void` implementa `Illuminate\Contracts\Validation\ValidationRule`, il cui contratto vendor tipizza `$value` come `mixed`. |
| `tests/Fixtures/ScheduleArgumentsProbe.php` | `getState(): mixed` / `public mixed $fakeState` rispecchiano il contratto vendor `Filament\Tables\Columns\Column::getState(): mixed` che la sonda di test deve rispettare per LSP. |
| `app/Actions/Command/GetCommandArgumentsActions.php` | Il campo `default` in `array{name: string, default: mixed, required: bool}` rispecchia `Symfony\Component\Console\Input\InputArgument::getDefault()`, genuinamente `string\|array\|bool\|int\|float\|null`. |
| `app/Actions/GetTaskFrequenciesAction.php`, `app/Http/Livewire/Schedule/Crud.php` | `config('totem.frequencies')` ha una forma nidificata eterogenea (`parameters` varia da `false` a un array di definizioni di campo con chiavi diverse per tipo): payload di configurazione genuinamente polimorfo, verificato leggendo `config/*/totem.php`. |
| `app/Contracts/TaskContract.php`, `app/Contracts/TaskInterface.php` | `@param array<string, mixed> $input` per `store()`/`update()`; nessun implementer trovato nel modulo (`grep -rn "implements TaskContract\|implements TaskInterface"` vuoto) per verificare la forma reale dei campi: lasciato per bassa confidenza. |
| `app/Models/Schedule.php` | `Collection<int|string, mixed>` in `getEnvironments()`: la colonna `environments` e' cast `array`, quindi usarla come chiave di `pluck()` produrrebbe una chiave non scalare a runtime; forma incerta/potenzialmente un bug pre-esistente indipendente, non affrontato in questa story (bassa confidenza, fuori scope). |
| 18 file gia' `dirty` (29 occorrenze) | Non valutati in profondita': modificarli avrebbe richiesto isolare un singolo hunk dentro un diff gia' esteso di un'altra sessione, rischio di collisione non giustificato per il valore atteso. |

Tentativo poi annullato: `app/Datas/CommandData.php` (`$arguments` da `array<int, array<string,
mixed>>` a `array{name: string, description: string, required: bool}>`, forma reale
dell'unico chiamante `GetCommandsAction::execute()`): PHPStan segnalava `argument.type`
perche' il chiamante stesso porta un `@var array<int, array<string, mixed>>` largo, dentro
`app/Actions/Command/GetCommandsAction.php`, gia' file dirty di un'altra sessione. Sistemarlo
per bene richiedeva toccare quel file: annullato, lasciato come `mixed` documentato.
