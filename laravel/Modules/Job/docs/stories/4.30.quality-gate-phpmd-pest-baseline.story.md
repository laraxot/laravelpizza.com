errori (verificato oggi, 2026-09-04, da una sessione precedente con e senza path arg dopo
un refresh di `ide-helper:generate/meta/models`), il resto del gate va chiuso: phpmd,
phpinsights, pest, coverage, git su tutti i remote.

## Passi eseguiti e risultati (numeri reali)

1. **`php -l` sweep** su `Modules/Job/**/*.php`: nessun errore di sintassi.
2. **PHPStan baseline**: `clear-result-cache` + `analyse Modules/Job --no-progress
   --error-format=table` → **0 errori** (confermato, invariato dalla misura precedente
   della giornata). Verificato di nuovo dopo i 2 fix: ancora **0 errori**.
3. **PHPMD** (`./tools/phpmd.sh Modules/Job/app text ../docs/phpmd.ruleset.xml`): **123
   finding prima → 121 dopo**. 2 fix reali applicati:
   - `app/Actions/ExecuteTaskAction.php`: `MissingImport`: `throw new
     \BadMethodCallException(...)` → `use BadMethodCallException;` + `throw new
     BadMethodCallException(...)`.
   - `app/Models/Policies/JobBasePolicy.php`: `UnusedLocalVariable`: rimossa `$xotData =
     XotData::make();` (dead code, mai usata) e il relativo import ora superfluo.

   Dettaglio completo dei 121 finding rimanenti (perche' non toccati) in
   `docs/coverage.md`, sezione "2026-09-04: Quality-gate closure". Riassunto: convenzione
   di progetto (`$_user`/`$_task` ecc. nelle Policy), naming legacy snake_case sparso su
   decine di siti Livewire/Filament (rischio di rottura senza test affidabili), 4
   CyclomaticComplexity gia' note dal 2026-07-20, 5 BooleanArgumentFlag (refactor di API
   pubblica), 2 CouplingBetweenObjects (redesign architetturale), stile puro
   (ElseExpression/IfStatementAssignment/LongVariable).

   **Finding non-phpmd trovato investigando i CyclomaticComplexity/duplicazioni**: due
   coppie di classi duplicate: `Filament\Columns\{ScheduleArguments,ScheduleOptions}`
   (in uso/testate; `ScheduleOptions::getTags()` e' pero' dead code, corpo commentato,
   ritorna sempre `[]`) vs `Filament\Tables\Columns\{ScheduleArguments,ScheduleOptions}` +
   `Filament\Fields\Repeater` vs `Filament\Forms\Components\Repeater` (implementazioni
   diverse, zero riferimenti in tutto il monorepo, verificato con `grep -rln` su
   `Modules/` e `Themes/`). Sembra una migrazione Filament 4→5 lasciata a meta'. **Non
   toccato**: consolidare richiede capire quale versione e' quella corretta, fuori scope
   per una chiusura gate meccanica: proposto come story dedicata di follow-up.
4. **phpinsights**: **non installato** in questo repository (`./vendor/bin/phpinsights
   --version` → "package not found"; coerente con la memoria
   `pest5-incompatibile-con-phpinsights`: rimosso perche' incompatibile con Pest 5). Non
   eseguito.
5. **Pest**: comando corretto verificato essere quello con la config root, non quella del
   modulo (`Modules/Job/phpunit.xml` ha `bootstrap="vendor/autoload.php"` relativo, path
   inesistente in questo layout: pre-esistente, non toccato):
   `env XDEBUG_MODE=coverage ./vendor/bin/pest "Modules/Job/tests/" --configuration
   phpunit.xml --no-coverage`. 330 test totali. **Non deterministico su run consecutivi
   identici**: run 1 → 330 failed/0 assertions (tutti con lo stesso errore di bootstrap,
   `Typed property Modules\Xot\Datas\ComponentFileData::$name must not be accessed before
   initialization` in `Modules/Xot/app/Actions/Blade/RegisterBladeComponentsAction.php:28`,
   chiamato da `XotBaseServiceProvider.php:137`); run 2 → 38 failed/292 passed (1151
   assertions); run 3 → timeout a 400s senza risultato, con `ps aux` che mostrava
   **contemporaneamente** run Pest di altre sessioni su `Modules/Media`, `Modules/AI`,
   `Modules/Activity` sullo stesso DB MySQL `_test` condiviso: conferma diretta di
   contesa multi-agente, non un difetto del modulo Job. Isolando
   `tests/Unit/Traits/FormatSecondsTest.php` (non toccato da questa story, nessuna
   relazione con Blade component registration) → **PASS 2/2**. Conferma: l'errore e' in
   `Modules\Xot`, si manifesta solo su suite intera in sequenza, non e' causato da questa
   story ne' dal modulo Job. Non tentato un fix dell'ambiente (fuori scope, istruzione
   esplicita di non forzare fix ambientali).
6. **Coverage**: non misurabile in modo affidabile: nessun run della suite completa
   raggiunge una fine coerente per generare un report clover/html valido. Nessun test
   aggiunto (i 2 fix erano rimozione di codice morto/import, zero logica nuova da coprire):
   baseline lasciata cosi' com'e' in `docs/coverage.md`, nessun numero inventato.
