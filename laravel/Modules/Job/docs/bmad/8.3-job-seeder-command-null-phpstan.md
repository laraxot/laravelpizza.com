# 8.3: Seeder: `command` null (PHPStan `method.nonObject` / `return.type`)

## Scopo (perché)
Nei seeder (Job, User, Roles) il valore di ritorno di `parent::command()` è `?Command`: quando la classe base non è eseguibile standalone (o quando `command` non è impostato) il valore è `null` e le chiamate successive (`->call()`, `->ask()`) falliscono a runtime. PHPStan lo segnala come `method.nonObject` / `return.type`: è un **bug di robustezza**, non un problema di stile: il seeder può crashare.

## Pattern di fix (DRY, riusabile)
- Estrarre un helper/trait condiviso in `Xot` (es. `XotBaseSeeder` o un'Action `ResolveSeedCommandAction`) che: (1) recupera il command con gestione del caso `null`; (2) se assente, esegue la logica del seeder in modo esplicito (loop su modelli) invece di fallire; (3) restituisce un tipo non-null.
- Applicare lo stesso pattern a `JobDatabaseSeeder`, `UserSeeder`, `UserMassSeeder`, `RolesSeeder`.

## Vincoli
- Nessun `mixed`; nessun silenziamento; nessun `migrate:fresh`; i seeder restano idempotenti.
- Verifica: `php -d memory_limit=2G ./vendor/bin/phpstan analyse Modules/Job --no-progress` e `Modules/User`.
