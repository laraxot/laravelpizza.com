# 12.4: igiene git residua (queue.pid, graphify-out, .aaa) + incidente agente concorrente

**Perché.** Incarico esplicito: ripulire i residui del rebase abortito su `dev`
(`git reflog`: `rebase (abort): returning to refs/heads/dev`, HEAD@{1}→{0} `2f146e72`→
`aa0956f3`). Elenco atteso: marker annidati in `README.md`/`.github/contributing.md`,
due file `.aaa` sospetti, `queue.pid` tracciato, 8 file `graphify-out/` tracciati
nonostante `.gitignore` (riga `graphify-out`, funzionalmente equivalente a
`graphify-out/`, non duplicata).

## Incidente: collisione con agente concorrente (evidenza)

Appena iniziato l'intervento, `git diff README.md` è fallito con "File has been
modified since read": il working tree stava cambiando sotto i piedi. Verifica:

```
$ cat laravel/Modules/Job.lock
LOCKED at 2026-09-22T18:14:33+02:00
Task: fix-rebase-conflict-job-module
Agent: unknown

$ cat laravel/Modules/Job/README.md.lock   # (presente alle 18:18, rilasciato ~18:23)
LOCKED at 2026-09-22T18:18:23+02:00
Task: job-12.3-hygiene
Agent: cursor-grok
```

Un secondo agente (`cursor-grok`, via il lock-holder "unknown" di `Job.lock`) stava
eseguendo **lo stesso identico task** in parallelo, ed è l'autore reale della story
[12.3](./12.3.root-hygiene-conflict-markers.story.md) (marker README/contributing,
rimozione `ARCHITECTURE.md`/`Untitled`/backup datati/`lang/it/.php`, PHPStan verificato
`[OK] No errors`). Applicando lo standing order "non forzare, segnala e salta" (pilastro
4), questa story **non duplica** il lavoro di 12.3: si limita a (a) verificare
indipendentemente il risultato di 12.3 sui due file marker, (b) coprire gli item **non
in scope di 12.3**: `queue.pid`, `graphify-out/`, `.aaa`.

Per evitare l'`index git condiviso` (memoria `feedback-git-index-is-shared-between-agents`),
non è mai stato usato `git add -A`/`commit -a`: solo `git add <path>` mirato sui file di
competenza di questa story, lasciando intatti nel working tree i file ancora
unstaged dell'altro agente (`docs/bmad/*`, backup, `ARCHITECTURE.md`, nuove story).

prima di essere ricommittato, coerente con la firma nota del daemon auto-commit,
memoria `project-local-autocommit-daemon-per-module.md`).

## `.aaa`: evidenza per la rimozione (non rinomina)

```
$ git log --all --diff-filter=A --oneline -- '*MonitoredScheduledTask*' | tail -1
b5fb9107 .   # commit INIZIALE del repo (2026-01-20), file già .aaa da subito
$ grep -rn "MonitoredScheduledTask" app/ database/ tests/ config/ routes/ | grep -v '\.aaa:'
(nessun risultato: zero riferimenti fuori dai due file stessi)
$ grep -n "schedule-monitor" ../../composer.json ../../composer.lock
(nessun risultato: dipendenza spatie/laravel-schedule-monitor non installata)
```

Contenuto: classi stub (`class MonitoredScheduledTask extends BaseModel {}`) col vero
`extends \Spatie\ScheduleMonitor\Models\...` commentato. **Non esiste evidenza che il
nome originale fosse `.php`**: contrariamente all'ipotesi di partenza, la storia mostra
`.aaa` fin dal commit iniziale. Verdetto: codice morto/mai attivato (dipendenza
assente, zero riferimenti, mai valido come `.php`) → **rimozione** (`git rm`, non
`--cached`), non rinomina: rinominare avrebbe "reinventato" un file mai esistito come
`.php` funzionante.

## Fix applicati (commit separato da 12.3)

1. `git rm --cached app/Console/Commands/queue.pid` + `*.pid` in `.gitignore` (assente
   prima; il file conteneva un PID runtime, `9252`, mtime coincidente con l'avvio
   dell'agente concorrente: probabilmente rigenerato da un worker in esecuzione).
2. `git rm --cached` sugli 8 file `graphify-out/` tracciati (restano su disco,
   rigenerabili con `graphify update .`); `.gitignore` riga 152 `graphify-out` lasciata
   com'è (equivalente a `graphify-out/`, nessuna duplicazione).
3. `git rm app/Models/MonitoredScheduledTask.aaa app/Models/MonitoredScheduledTaskLogItem.aaa`
   (rimozione reale, evidenza sopra).
4. Verifica indipendente marker README/contributing (nessuna modifica necessaria,
   già corretti da 12.3) + staging nello stesso commit per non lasciarli esposti a
   un futuro `dummy_push()`/merge automatico del daemon (memoria
   `project-local-autocommit-daemon-per-module.md`).
